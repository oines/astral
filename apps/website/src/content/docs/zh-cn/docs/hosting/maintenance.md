---
title: "升级与备份"
description: "更新 Server 和电脑服务，并完整保存历史与工作文件。"
---

升级前先确认当前版本、数据位置和正在运行的任务。预发布版本可能改变数据格式，不要默认旧数据一定可以自动迁移或回退。

## 更新 Desktop 或 Server

Desktop 的本机电脑服务随 Desktop 更新；独立 Server 的本机电脑服务随 Server 更新。当前没有已完成的桌面自动更新流程，按实际发布内容或源码构建结果替换程序并重启。

保留原来的数据目录和启动参数。不要因为换了可执行文件，就把 `--data` 指向空目录。

## 更新远程电脑或容器

打开 **设置 → 电脑 → 电脑详情 → Daemon 维护**，使用该电脑显示的更新命令。

- 远程电脑：在目标机器执行，更新服务并重启当前用户的后台服务。
- 容器：在宿主机执行，更新并重启同一个容器，保留环境和数据。

两者都会中断正在运行的任务，保留电脑身份与数据。容器更新不替换基础镜像。

## 备份哪些内容

| 对象 | 需要保留的内容 |
| --- | --- |
| Server | 完整数据目录，包括数据库、`master.key` 和 `computer-identity/` |
| 本机及远程电脑 | 电脑服务数据、Bot 工作目录和实际项目文件 |
| 容器 | 数据卷，以及需要保留的容器可写层或重建方法 |

只复制数据库不够：缺少加密密钥可能无法读取已保存的凭据，缺少电脑连接身份会影响现有电脑对 Server 的信任。

最直接的备份方法是停止 Desktop 或 Server，再复制完整数据目录。使用运行中备份时，需要采用一致的 SQLite 备份方式，不能只随手复制一个正在写入的数据库文件。

## 找到数据目录

优先查看启动日志、电脑详情与实际启动参数。没有覆盖时，默认根目录为：

- macOS：`~/Library/Application Support/astral`
- Windows：`%APPDATA%\astral`
- Linux：`$XDG_CONFIG_HOME/astral`，通常为 `~/.config/astral`

Server 数据通常在根目录的 `server/`，本机电脑数据在 `computers/`。自定义的 `--data`、`--computers-dir` 或环境变量优先。

## 恢复后检查

先用匹配版本恢复并启动，确认历史、模型连接、电脑在线状态和聊天账号，再恢复任务。不要让两个 Server 进程同时写同一个数据目录。
