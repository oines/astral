从下面选择与你遇到的情况最接近的一项。页面有具体错误时，保留那段文字：它通常能指出失败的是登录、模型连接，还是某台电脑上的操作。

## 网页打不开或无法登录

### 浏览器一直连接失败

如果使用官方 Linux 安装，在服务器终端检查：

```sh
systemctl --user status astral-server.service
```

- 服务未运行：用 `systemctl --user start astral-server.service` 启动；启动失败时，查看 `journalctl --user -u astral-server.service` 的错误。
- 服务在运行：确认访问的是服务器实际 IP 和端口。默认是 `http://服务器IP:4545`，远程浏览器中的 `127.0.0.1` 指浏览器自己的电脑。
- 地址正确：在服务器本机执行 `curl http://127.0.0.1:4545/health`。如果本机可访问而远程不行，检查服务器防火墙、云平台安全组和反向代理。自定义端口时使用自己的端口。

桌面版默认不开放直接远程管理，需要在 **设置 → 安全与访问** 中开启；独立 Server 默认开启，除非启动配置明确关闭。

### 网页能打开，但提示无法登录

| 页面提示或操作后的现象 | 处理方法 |
| --- | --- |
| 尚未设置网页登录 | 在服务器执行 `astral auth setup --username admin`，按提示设密码后登录 |
| 用户名或密码错误 | 核对输入；忘记密码时按[账户恢复](/zh-cn/docs/hosting/security/#无法登录时恢复)处理 |
| 修改用户名或密码后退出 | 使用修改后的信息重新登录 |
| 验证器或 Passkey 不可用 | 尝试其他已配置方式或恢复码；Passkey 要使用添加时的 HTTPS 域名 |
| `403 unrecognized management host` | 在服务器执行 `astral config hostnames show`；需要恢复访问时按[主机名限制](/zh-cn/docs/hosting/security/#主机名限制)处理 |

## 安装下载失败

GitHub 连接失败或超时时，可以尝试[完整备用安装命令](/zh-cn/docs/hosting/server/#国内无法访问-github)。它同时处理安装脚本和后续程序下载。

如果错误是校验失败、版本不匹配或不支持该版本，先保留错误信息。安装指定旧版本时使用该发行版附带的安装器，不要跳过校验继续运行。

## 模型没有回复，或不能执行任务

先在 Astral 网页或桌面版中打开同一个 Bot 的会话，发一句简单的话，例如“请回复连接正常”。

- **连文字都没有回复**：查看会话中的错误。账号额度、API Key、服务地址或模型不可用等问题，需要在对应模型连接中处理。自定义模型服务必须从运行 Astral 的机器可达。
- **能聊天，但不能读取文件或执行命令**：检查会话选中的电脑是否在线，以及这个 Bot 是否有权使用它。再确认所选模型支持工具调用。
- **已经开始执行，但某个命令失败**：展开那次执行记录，查看实际命令、所在电脑和错误。缺少软件、文件路径错误等问题，应在执行任务的电脑上处理。

模型连接的准备和配置见[模型与搜索](/zh-cn/docs/usage/models/)。

## 电脑一直离线

先确认目标电脑开机、未休眠，并能访问 Astral 所在机器。然后在**那台已接入的电脑**上检查：

| 要检查什么 | 命令 |
| --- | --- |
| 是否连上原来的 Astral | `astral computer status` |
| 连接程序的后台服务是否运行 | `astral computer service status` |
| 后台服务日志 | `astral computer service logs` |

这些命令适用于通过接入安装器配置的远程裸机电脑。多个安装时按提示选择，或指定原来的 `--root`。容器电脑先在 Docker 宿主机检查容器是否运行。

新接入命令过期时，回到添加电脑页面生成一条新的命令。如果更换了 Server 地址，已有电脑仍使用保存的原地址，需要检查那条连接是否还能到达服务器。

## 创建容器失败

本机容器入口会显示实际检测结果和处理入口。按提示完成配置后重新检测；Linux 后台账号需要 Docker 权限时，见[容器运行环境配置](/zh-cn/docs/computers/containers/)。

已经进入创建流程而失败时，查看创建日志里的失败阶段。首次拉取环境镜像可能需要较长时间；保留具体下载或容器启动错误，才能继续定位。

## 平台账号已连接，但 Bot 不回复

1. 先在 Astral 内给同一个 Bot 发一个简单任务，确认模型和电脑正常。
2. 在平台账号设置中确认目标私聊或群聊已经接入。群聊先真正 @ Bot，或回复它发出的消息。
3. 在原聊天发送“请在这个聊天中回复：连接成功”。到 Astral 对应会话查看是否收到了消息。

**Astral 没收到消息**时，检查平台的接收权限与事件配置；**收到并处理了，但原聊天没回复**时，查看会话里的发送结果和平台是否限制发送。

继续按对应平台检查：[Telegram](/zh-cn/docs/chat/telegram/)、[QQ](/zh-cn/docs/chat/qq/)、[微信](/zh-cn/docs/chat/weixin/)、[飞书](/zh-cn/docs/chat/feishu/)。

## 文件打不开或没发出去

先确认文件所在电脑在线，原文件仍存在。文件操作使用的是会话选中的电脑；另一台电脑上的同名路径可能没有这个文件。

平台发文件失败时，查看实际发送错误。若结果不确定，先到目标聊天确认有没有收到，再决定是否重发。文件的提供、保存和下载方式见[文件与结果](/zh-cn/docs/usage/files/)。

## 用户服务管理器连接失败

这一项适用于 Linux 终端中 `systemctl --user` 报 `Failed to connect to bus` 的情况。

先确认终端使用的是安装 Astral 的同一系统账号。某些 `sudo -i` 等会话没有设置用户服务需要的环境，可以在该账号的终端执行：

```sh
export XDG_RUNTIME_DIR="/run/user/$(id -u)"
export DBUS_SESSION_BUS_ADDRESS="unix:path=$XDG_RUNTIME_DIR/bus"
systemctl --user status astral-server.service
```

如果对应目录下没有 `bus`，检查安装器先前报告的准备错误，以及系统的 systemd 用户会话和 D-Bus 组件。不要套用另一账号的 UID 或运行目录。

## 仍然无法解决

在 **设置 → 关于与诊断** 找到版本，向 [GitHub Issues](https://github.com/oines/astral/issues)提供：

- 使用桌面版还是 Server，以及操作系统。
- 从哪一步开始出现问题，原本希望看到什么，实际看到了什么。
- 完整的相关错误；涉及电脑或聊天时，注明电脑类型或平台接入方式。

提交前删去密码、API Key、Token、恢复码和私人聊天内容。
