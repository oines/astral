title: "连接电脑"
description: "选择 Bot 执行任务的机器，完成连接和授权。"
---

Bot 需要一台电脑来读写文件和执行命令。它可以使用安装 Astral 的机器，也可以使用另一台设备。连接后，还要明确允许哪个 Bot 使用它。

## 使用服务所在电脑

只想处理当前 Astral 主机上的文件时，在**设置 → 电脑 → 添加电脑**中选择**使用服务器所在机器**即可。Desktop 通常使用安装应用的电脑；通过浏览器访问独立 Server 时，“本机”指 Server 所在机器。

例如，你在笔记本上打开办公室 Server 的网页，使用这个入口接入的是办公室机器。要使用笔记本上的文件，需要把笔记本另行接入，或上传所需文件。

本机操作使用运行 Astral Server 的系统账号权限。电脑显示在线后，继续下面的[授权与试用](#授予-bot-使用权限)。如果想给 Bot 单独的 Linux 环境，可改用[容器电脑](/zh-cn/docs/computers/containers/)。

## 连接其他机器

在**设置 → 电脑 → 添加电脑 → 连接其他机器**生成命令，然后到**要接入的那台电脑**打开终端运行：macOS 和 Linux 使用 Shell，Windows 使用 PowerShell。

生成前需要决定两件事：

- **服务器地址**：目标电脑必须能访问这个 Astral Server。处于同一个局域网时可用局域网地址；通过 VPN 连接时可用 VPN 地址。`127.0.0.1` 只指当前机器，不能用它连接另一台机器上的 Server。
- **操作系统**：选择运行命令的电脑所用系统。若创建容器，选择的是容器所在电脑的系统。

使用希望 Bot 拥有文件权限的系统账号运行**完整命令**。它会安装后台服务和 `astral` 命令，完成后回到 Astral 等待这台电脑显示在线。终端中的错误会说明连接或安装停在哪一步。

命令包含临时配对凭据，只在预定电脑上运行。过期后重新生成。目标电脑需要能下载对应版本的官方发行文件；未发布的源码开发版本需要自行准备程序，见[从源码构建](/zh-cn/docs/hosting/build-from-source/)。

电脑主动连接 Server，接入地址支持 HTTP 和 HTTPS，电脑通道会加密并校验服务器身份。浏览器登录的网络要求见[运行 Server](/zh-cn/docs/hosting/server/)。

## 授予 Bot 使用权限

电脑在线后，进入**设置 → Bot → 目标 Bot → 电脑权限**授权，并按需将它设为默认电脑。回到该 Bot 的会话，选择这台电脑，再发一个只读任务确认：

> 告诉我当前电脑的名称和工作目录，并列出工作目录里的文件，不要修改任何内容。

核对返回的位置是否符合预期。到这里，电脑才进入这个 Bot 的实际工作流程。默认电脑用于新会话；已有会话保留原选择。

授权后，Bot 可按电脑服务账号的权限读写文件和运行命令，访问范围不限于默认工作目录。面对公开群聊或不可信资料，先阅读[环境与权限建议](/zh-cn/docs/start/safe-use/)。

## 连接后还不能使用

| 情况 | 检查什么 |
| --- | --- |
| 一直等待接入 | 查看目标电脑终端中的错误，确认它能访问生成命令使用的 Server 地址。 |
| 安装时下载失败 | 确认能访问官方发行资源；无法访问 GitHub 时，使用下方备用下载方式。 |
| 脚本提示已有 `astral` 命令 | 安装器不会覆盖其他命令。若以前手动把旧版 `astral.exe` 所在目录加入 PATH，先从 PATH 移除该目录，重新打开终端后再运行接入命令；不要删除后台服务正在使用的程序或数据。 |
| 电脑在线，但会话里没有它 | 检查当前 Bot 的电脑权限。连接电脑本身不会自动授权。 |
| 能连接，但读不到文件 | 确认文件属于这台电脑，并检查运行后台服务的系统账号是否有读取权限。 |
| 原来可用，现在离线 | 确认目标电脑和 Server 都在运行，再检查目标电脑的后台服务状态。 |

## 目标电脑无法访问 GitHub

在目标电脑终端先设置公共下载代理，再粘贴网页生成的完整接入或更新命令。保留命令中的 Server 地址和配对参数。

macOS / Linux：

```sh
export ASTRAL_GITHUB_PROXY=https://gh-proxy.org/
```

Windows PowerShell：

```powershell
$env:ASTRAL_GITHUB_PROXY = 'https://gh-proxy.org/'
```

这是第三方公共下载服务，只用于安装脚本和 GitHub 发行文件，电脑与 Server 的连接不经过它。详细说明见[备用下载](/zh-cn/docs/hosting/server/#国内无法访问-github)。取消当前终端的选择：Shell 使用 `unset ASTRAL_GITHUB_PROXY`，PowerShell 使用 `$env:ASTRAL_GITHUB_PROXY = ''`。

## 更新已连接的 Daemon

Daemon 是运行在已连接电脑上的 Astral 服务。远程电脑可在详情页的**Daemon 维护 → 更新 Daemon**更新；服务所在电脑的本机 Daemon 随 Desktop 或 Server 更新。

更新会中断正在运行的任务，请先安排好当前工作。Astral 会下载、校验和重启服务；等电脑重新上线后检查版本。电脑身份、凭据和工作文件保留。若提示 Daemon 比 Server 新，可同时安排更新 Desktop 或 Server。

电脑离线、不支持界面更新或更新失败时，使用同一区域提供的更新命令。普通电脑的命令在那台电脑上运行；容器命令在容器所在的宿主机运行。普通电脑始终沿用原接入系统账号的权限。

## 后台服务与断开

远程接入的后台服务属于运行接入命令的系统账号。macOS 使用用户 LaunchAgent，Linux 使用用户 systemd，Windows 使用当前用户的计划任务。换一个账号接入，也会改变 Bot 能访问的文件范围。

Linux 普通账号接入前需要可用的用户服务；接入不会自动提权，也不会自动为普通账号配置退出登录后继续运行的 linger。若你需要以 root 接入，直接登录 root 或先运行 `sudo -i`，再执行完整接入命令，避免沿用其他账号的环境。此时 Bot 的命令也拥有 root 权限。

root 后台接入会准备用户服务并启用 linger，使它不依赖登录会话运行；准备失败会在配对前停止。linger 影响整个账号，卸载 Astral 不会自动关闭它或停止整个用户管理器。前台运行和容器接入不执行这项准备。

## 断开与停用电脑

先停止相关会话，并检查仍在运行的工作，再按目标选择动作：

- 只收回某个 Bot 的使用权：在该 Bot 的电脑权限中撤销授权。
- 断开所有 Bot 与这台电脑：在电脑详情选择**撤销连接**。撤销后可以删除 Astral 中的电脑登记。
- 停止目标电脑上的后台服务：在目标电脑使用当初接入的系统账号执行以下命令。

```sh
astral computer service stop
astral computer service status
```

以后需要继续使用，可运行 `astral computer service start`。长期停用时，卸载后台服务：

```sh
astral computer service uninstall
```

如果安装了多个实例，按提示选择；无人值守命令可加 `--root /path/to/computer` 指定数据目录。旧版自定义目录未被发现时，可从电脑详情复制路径。

撤销授权阻止后续操作，不会撤销已完成的文件修改。删除电脑登记或卸载服务会保留工作文件；删除登记也不负责卸载服务、删除容器或数据卷。容器在宿主机的容器管理器中停用，删除前先备份。Desktop 的本机服务随应用运行，按桌面后台运行设置停用。
