---
title: "连接电脑"
description: "把本机或其他电脑接入 Astral，再授权给对应的 Bot 使用。"
---

Bot 需要一台在线的**电脑**来读写文件和运行命令。你可以直接用安装 Astral 的这台机器，也可以把家里的台式机、笔记本或远程服务器接入进来。

接入分两步：**1. 连接电脑 → 2. 给 Bot 授权**。只连接不授权，会话里不会出现这台电脑。

## 方式一：使用当前主机

只想操作运行 Astral 的这台机器，打开 **设置 → 电脑 → 添加电脑**，选择**使用服务器所在机器**即可。

- **桌面版**：指你安装 Astral 桌面应用的本机。
- **独立 Server**：指部署 Server 的那台服务器（不是你打开浏览器的笔记本）。

操作会沿用运行 Astral Server 的系统账号权限。电脑上线后，直接跳到[授予 Bot 使用权限](#授予-bot-使用权限)。如果需要独立的 Linux 沙盒环境，改用[容器电脑](/zh-cn/docs/computers/containers/)。

## 方式二：连接其他机器

在 **设置 → 电脑 → 添加电脑 → 连接其他机器** 生成接入命令，再复制到**目标电脑**的终端运行（macOS / Linux 用 Shell，Windows 用 PowerShell）。

生成命令前确认两项：
- **服务器地址**：目标电脑必须能访问这个地址（同一局域网填局域网 IP，VPN 内填 VPN 地址）。`127.0.0.1` 只指向目标电脑自身，不能用来连别的机器。
- **操作系统**：选实际运行命令的机器系统（创建容器时选宿主机系统）。

用你希望 Bot 拥有文件权限的系统账号执行**完整命令**。脚本会安装后台服务与 `astral` 命令，完成后回到 Astral 等待设备显示在线。

:::note[连接安全与临时凭据]
接入命令带有临时配对凭据，仅在目标电脑上使用，过期重新生成即可。电脑主动向外连接 Server，支持 HTTP 与 HTTPS 接入地址，通道会加密并校验 Server 身份。
:::

## 授予 Bot 使用权限

电脑显示在线后，去 **设置 → Bot → 目标 Bot → 电脑权限** 勾选授权（按需设为默认电脑；默认仅影响新会话）。

回到该 Bot 的会话，选中这台电脑，发一条只读指令验收：

> 告诉我当前电脑的名称和工作目录，并列出工作目录里的文件，不要修改任何内容。

:::caution[权限边界提醒]
Bot 拥有接入时所用系统账号的文件和命令权限，范围不限于默认工作目录。面对公开群聊或外来资料，请先读[权限与隐私](/zh-cn/docs/start/safe-use/)。
:::

## 控制电脑能否调用 Astral API

添加电脑时可决定是否打开**启用 Astral API**（之后也可在电脑详情随时修改）：

| 场景 | 建议设置 |
| --- | --- |
| 远程构建机、只需跑命令和读写文件 | **保持关闭**（新接入的远程电脑与远程容器默认关闭） |
| 信任的机器，需要调用 Astral 历史/API 或通过本地端点触发事件唤醒 | **打开**（服务器本机与本机容器默认开启） |

关闭后，Server 会拦截这台电脑发起的 API 请求和新事件投递（对所有使用它的 Bot 生效），但不影响 Bot 正常在这台电脑跑命令和读写文件；旧版 Daemon 无需升级即可生效。若连接凭据不慎泄露，请直接[撤销连接](#断开与停用电脑)后重新配对。

## 更新已连接的 Daemon

Daemon 是运行在已连接电脑上的 Astral 后台服务。本机 Daemon 随 Desktop / Server 一起更新；远程电脑在详情页点击 **Daemon 维护 → 更新 Daemon** 即可。

:::caution[更新会中断当前任务]
更新过程会重启后台服务，请先等重要任务结束再操作。电脑身份、凭据和工作文件都会保留。
:::

如果目标电脑离线或在线更新失败，复制同一区域提供的更新命令，在对应电脑（容器则在宿主机）的终端手动执行。

## 目标电脑无法访问 GitHub

如果目标电脑直连 GitHub 失败，先在终端设置第三方下载代理，再粘贴网页生成的完整接入或更新命令（代理只用于下载安装脚本与发行文件，电脑与 Server 的日常通信不走代理；详见[备用下载](/zh-cn/docs/hosting/server/#国内无法访问-github)）：

```sh
# macOS / Linux（取消用 unset ASTRAL_GITHUB_PROXY）
export ASTRAL_GITHUB_PROXY=https://gh-proxy.org/
```

```powershell
# Windows PowerShell（取消用 $env:ASTRAL_GITHUB_PROXY = ''）
$env:ASTRAL_GITHUB_PROXY = 'https://gh-proxy.org/'
```

## 常见问题排查

| 现象 | 排查方向 |
| --- | --- |
| 一直显示等待接入 | 看目标终端的报错，确认它能连通命令里的 Server 地址。 |
| 安装时下载失败 | 按上方配置 `ASTRAL_GITHUB_PROXY`；未发布的开发版需[从源码构建](/zh-cn/docs/hosting/build-from-source/)准备程序。 |
| 提示已有 `astral` 命令 | 安装器不会覆盖同名命令。若曾手动把旧版 `astral.exe` 目录加进 PATH，先移除后重开终端再跑（勿删运行中的服务文件）。 |
| 电脑在线，但会话里选不到 | 还没给当前 Bot 授权，去 **电脑权限** 勾选。 |
| 读不到文件 | 确认文件确实在这台电脑上，且运行后台服务的系统账号有读权限。 |
| 传大文件时反复掉线 | 升级 Astral Server（Desktop 随应用升级）及参与传输的电脑上的 Daemon。 |

## 断开与停用电脑

先在会话中停止正在运行的任务，再按需要选择力度：

- **收回单个 Bot 权限**：在对应 Bot 的**电脑权限**取消勾选。
- **断开所有 Bot**：在电脑详情点**撤销连接**，随后可删除 Astral 中的登记记录。
- **停止或卸载目标电脑的后台服务**（用当初接入的系统账号在目标电脑运行）：

```sh
astral computer service stop      # 暂停（恢复用 start，查看用 status）
astral computer service uninstall # 长期停用，卸载后台服务
```

:::caution[删除电脑登记的后果]
- **永久删除登记**会同时删除该电脑上的全部事件唤醒端点，并清除尚未进入会话的待处理事件（已有会话历史和其他电脑的事件保留）。
- **删除登记或卸载服务不会删除你的工作文件**，也不会自动停止或删除远程 Daemon 进程和 Docker 容器；容器请到宿主机自行停用和备份。
:::

<summary>查看连接 IP、慢网络行为、Linux 后台服务与多实例细则</summary>

- **连接 IP 与可信代理**：电脑在线时，详情页显示**连接 IP**。直连显示 Server 看到的对端地址；若经过[可信代理配置](/zh-cn/docs/hosting/server-options/#代理位于另一台机器)（如 Cloudflare Tunnel），显示转发后的客户端公网出口 IP，用于排查连接问题。
- **慢网络与断线行为**：网络慢会让输出和文件传输变慢，Astral 会在电脑端持续缓存待传输出。一旦确认电脑与 Server 断连，运行中的命令会被停止，重连后不会自动重跑；结果不明时先检查文件再重试。关闭浏览器标签不会断开电脑。
- **后台服务归属与 Linux linger**：macOS 用用户 LaunchAgent，Linux 用用户 systemd，Windows 用当前用户计划任务。Linux 普通账号需有可用的用户服务，接入不会自动提权或开启退出后保活（linger）。如需以 `root` 接入，请直接登录 root 或先执行 `sudo -i` 再粘贴命令；root 后台接入会自动配置用户服务与 linger（卸载 Astral 不会关闭整个账号的 linger，前台运行与容器接入跳过此步）。
- **多实例管理**：如果同一台电脑安装了多个实例，运行 `astral computer service` 命令按提示选择，或加 `--root /path/to/computer` 指定数据目录（旧版自定义目录可从电脑详情复制）。Desktop 的本机服务随桌面应用后台设置管理。

</details>
