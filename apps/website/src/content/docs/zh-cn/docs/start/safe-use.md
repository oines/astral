---
title: "安全使用 Astral"
description: "选择合适的执行环境，控制群聊权限，并了解数据会发送到哪里。"
---

Astral 可以读写文件、运行命令和操作聊天平台。开始交给它实际任务前，先决定哪些电脑、账号和资料适合开放给这个 Bot。

## 公开群聊使用独立环境

**强烈不建议把日常使用的电脑直接授权给公开群聊的 Bot。** 群聊接入后，群内任何成员都可以向 Bot 提出任务请求。Astral 按聊天授权，没有额外的成员指挥白名单；电脑命令也没有逐条强制审批。

建议按下面的方式准备：

1. 为公开群创建专用 Bot，和私人工作分开。
2. 只向它授权[独立容器](/zh-cn/docs/computers/containers/)或专用机器。可以在自己的电脑上运行容器；同时检查 Bot 的全部电脑权限，移除日常电脑的授权。只把容器设为默认电脑仍允许 Bot 切换到其他获准电脑。
3. 只提供任务需要的文件和凭据。避免把整个用户目录、SSH 密钥、Astral 数据目录或 Docker socket 挂进容器；只需读取的资料使用只读挂载。
4. 聊天账号保留“仅指定的聊天”，逐个添加需要接入的群。为平台账号授予完成任务所需的最少权限。

群管理操作使用平台 Bot 账号的身份。账号拥有禁言、踢人或发布公告等权限时，Bot 可以用这些权限执行请求，Astral 不会再按发话者是否为群管理员授权。容器只改变电脑执行环境，这些平台权限仍然有效。

## 电脑授权开放了什么

Bot 使用运行电脑服务的操作系统账号。该账号能访问的文件、网络和已配置工具，都可能被任务使用。使用普通账号，并把生产凭据和私人资料留在它无法访问的位置。以 root 接入会让命令拥有 root 权限。

工作目录用于确定任务从哪里开始，不能限制文件访问范围。人格说明、技能和 `AGENTS.md` 可以指导行为；真正的访问限制应由电脑授权、系统账号、文件权限和容器挂载控制。

## 分开私人会话和共享聊天

同一 Bot 可以通过内置 API 查询其他非私密会话的历史，并访问它获准使用的其他聊天。每个聊天各有一个会话，但电脑上的工作文件仍可能共享。

如果个人工作和群聊使用同一 Bot，可把个人会话[设为私密](/zh-cn/docs/usage/conversations/#私密会话)，阻止其他会话通过内置 API 发现、读取或修改它。私密会话仍会保存历史、调用所选模型服务，也仍可由网页登录账户管理。共享电脑上的文件和此前已经复制出去的信息需要另外保护。

对不同信任范围的群或用户，优先使用不同 Bot，并分别安排电脑权限和执行环境。

## 了解数据会发送到哪里

Server 会将执行任务所需的上下文交给你选择的模型服务，包括消息、读取的文件内容、命令输出和图片。搜索查询会发送给所选搜索服务。请按资料的敏感程度选择服务，并查看服务商的数据使用与保留设置。

原文件可以保存在自己的电脑上，同时其中的内容已作为模型输入发送出去。私密会话也遵循这条规则。

接入群聊后，平台交付的普通消息会进入上下文。关闭主动参与只控制 Bot 空闲时是否主动开始任务；这些消息仍可能用于后续回复或自动总结。接入前应让群成员了解这一点。

## 检查外来资料与技能

网页、群消息、附件和第三方项目文件可能含有诱导 Bot 执行其他操作的指令。安装技能或采用项目的 `AGENTS.md` 前，检查来源、说明和附带脚本。第一次使用不熟悉的工具或资料时，选用独立环境和可恢复的项目副本。

重要文件保留独立备份。处理生产数据前，先让 Bot 在测试数据上完成一次可检查的任务。

## 保护登录与凭据

网页登录账户拥有整个 Astral 的管理权限，包括私密会话。不要把它作为受限群成员账号分享。公网访问使用 HTTPS，并配置[两步验证或 Passkey](/zh-cn/docs/hosting/security/)。

妥善保存 API Key、平台 Token、恢复码和电脑接入命令。提交问题时，先检查日志、截图与导出的会话，去掉凭据和私人内容。完整 Server 备份包含聊天记录、身份和读取已保存凭据所需的密钥，应按敏感资料保管。

## 发现任务不合适时

先停止对应会话，再检查已经修改的文件和已发生的平台操作。停用聊天账号可以阻止后续消息接入；已经开始的电脑任务需要单独停止。

需要收回能力时，撤销 Bot 的电脑权限或电脑连接。需要停止或卸载远程后台服务时，按[断开与停用电脑](/zh-cn/docs/computers/connect/#断开与停用电脑)操作。停止任务或撤销权限都不会自动恢复此前的文件修改或撤回已发送的消息。
