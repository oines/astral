使用 Astral 前，最重要的决定是：**让哪个 Bot 使用哪台电脑，接触哪些文件，以及接收哪些人的任务。** 这页帮助你按自己的使用场景作出选择。

## 自己使用：先用文件副本试一次

Bot 在你授权的电脑上运行命令，可以使用该电脑服务账号能够访问的文件、网络和工具。第一次尝试整理、批量修改或删除文件时，先复制一份测试资料，完成后检查结果。

你可以在 **设置 → Bot → 目标 Bot → 电脑权限**中查看并收回授权。把某台电脑设为“默认”只是选择任务的起点；Bot 仍能使用其他已获授权的电脑。

**工作目录不是文件访问限制。** 即使你让 Bot 在一个项目文件夹内工作，系统账号能读取的其他位置仍可能被访问。需要真正隔开资料时，使用权限受限的系统账号、专用电脑或[独立容器](/zh-cn/docs/computers/containers/)。以 root 账号运行的电脑服务具有 root 权限。

<span id="公开群聊使用独立环境"></span>

## 接入群聊：给群安排专用 Bot

授权一个群后，群内成员可以向 Bot 交代任务。Astral 没有额外的成员指挥白名单，也没有每条电脑命令都必须人工批准的机制。

公开群聊应先这样准备：

1. [创建一个专用 Bot](/zh-cn/docs/usage/bots/)，用于这个群。
2. 只授权专用电脑或独立容器，并检查已授权列表中没有日常使用的私人电脑。
3. 只放入群任务需要的资料。容器不要挂载整个个人目录、SSH 密钥或 Docker socket。
4. 平台账号使用**仅指定的聊天**，只添加需要接入的群。

如果平台账号有禁言、踢人或发布公告的权限，Bot 也能使用这些能力。Astral 不会再根据提出任务的人是否是群管理员来限制它；请在聊天平台侧控制这个账号拥有的权限。

## 私人工作与共享聊天怎样分开

同一个 Bot 的不同会话可以使用它获准访问的其他会话和聊天信息。电脑上的文件也可能由这些会话共同使用。

如果仍要使用同一个 Bot，可以把个人会话[设为私密](/zh-cn/docs/usage/conversations/#私密会话)。这会阻止其他会话通过 Astral 的内置接口发现和读取它。网页登录管理员仍可管理这段会话；同一电脑上的文件需要另外安排访问权限。

不同信任范围的工作，使用不同 Bot 并分别授权电脑会更容易管理。已经复制到别处的信息需要在相应位置处理。

<span id="了解数据会发送到哪里"></span>

## 我的资料会发送到哪里

你选择的模型服务会接收完成任务所需的内容，例如对话、Bot 读取的文件、图片和命令输出。使用网页搜索时，查询内容还会发送给所选搜索服务。

因此，文件保存在自己的电脑上，也可能有部分内容作为请求发给模型。处理敏感资料前，请确认自己接受该模型服务的数据使用方式；私密会话也会调用你选定的模型。

接入群聊后，平台允许 Bot 收到的普通消息可以成为之后回复的参考。关闭“主动参与”会减少 Bot 主动发起的任务，但不会阻止这些消息进入它的上下文。接入共享聊天前，请让参与者了解这一点。

<span id="检查外来资料与技能"></span>

## 使用第三方资料或技能时

网页、附件和第三方项目可能夹带让 Bot 改做其他事情的指令。先用测试资料检查结果；安装技能前，查看来源、说明及其附带脚本。

人格说明、技能和项目中的 `AGENTS.md` 用于指导 Bot 做事。需要限制它能接触哪些资料时，仍应设置电脑权限和系统访问权限。

## 任务做错了怎么办

1. 在对应会话中点击**停止**。
2. 检查已经执行的命令、修改的文件和发出的消息；需要时从自己的备份恢复。
3. 如果来自聊天平台，停用该平台账号可暂停后续消息接入。已经运行的电脑任务仍需在会话中停止。
4. 必要时收回 Bot 的电脑授权，或[断开电脑](/zh-cn/docs/computers/connect/#断开与停用电脑)。

停止或收回权限只影响之后的操作，已经完成的文件修改和消息发送需要另行处理。

## 保管登录信息和备份

网页登录账号可以管理整个 Astral，包括私密会话，请不要把它当作受限群成员账号共享。远程访问时，按[登录与安全](/zh-cn/docs/hosting/security/)配置 HTTPS 和登录保护。

API Key、平台 Token、恢复码和电脑接入命令都应妥善保管。发截图或日志求助前，去掉这些内容和私人信息。完整备份也包含聊天记录和恢复凭据所需的密钥，请按敏感资料保存。
