用好 Astral 的核心原则只有一句话：**明确决定哪个 Bot 能动哪台电脑、能看哪些文件，以及能听谁的指令。**

## 个人使用：守住文件边界

Bot 在电脑上执行命令时，拥有**运行电脑服务的那个系统账号**的全部文件、网络与软件权限。

:::caution[工作目录不是权限墙]
即使你让 Bot 在某个项目目录里干活，只要系统账号能读到电脑上其他目录，Bot 同样能访问；以 `root` 运行的服务就拥有 `root` 权限。需要真正隔离文件时，请使用权限受限的系统账号、专用机器或[容器电脑](/zh-cn/docs/computers/containers/)。
:::

日常习惯建议：
- 第一次做批量重命名、整理或删除前，先用文件副本试跑一次。
- 随时可以在 **设置 → Bot → 目标 Bot → 电脑权限** 查看或收回权限。注意：“默认电脑”只是新会话的起点，Bot 仍可使用已授权列表里的其他电脑。

<span id="公开群聊使用独立环境"></span>

## 接入群聊：给群安排专用 Bot

:::caution[群里任何人都能发指令]
授权一个群后，群内成员都可以向 Bot 交代任务。Astral 不设额外的群成员白名单，也不会在执行每条命令前逐条弹窗审批；如果聊天账号本身有踢人、禁言或发公告权限，Bot 也能调用。
:::

接入公开群聊前，按这 4 步隔离风险：

1. **[新建一个专用 Bot](/zh-cn/docs/usage/bots/)**：不要和你的私人助手共用同一个 Bot。
2. **只授权专用电脑或 [Docker 容器](/zh-cn/docs/computers/containers/)**：检查电脑权限列表，确保日常私人电脑不在其中。
3. **只放入群任务必需的资料**：容器不要挂载整个个人主目录、SSH 密钥或 Docker socket。
4. **收紧聊天平台范围**：账号保持**仅指定的聊天**，只添加目标群，并在聊天平台侧限制账号自身的管理权限。

## 私人工作与共享聊天怎么分开

同一 Bot 下的不同会话可以互相查询上下文，也可能共用电脑上的同一份目录。

- **最省心的做法**：不同信任级别建不同 Bot，各自授权不同电脑。
- **共用同一个 Bot 时**：把个人会话[设为私密](/zh-cn/docs/usage/conversations/#私密会话)，其他会话就无法通过内置接口发现或读取它（注意：Web 管理员仍能查看，同一台电脑上的本地文件仍需靠目录或账号权限隔离）。

<span id="了解数据会发送到哪里"></span>

## 我的资料会发送到哪里

| 数据类型 | 发送目标 | 说明 |
| --- | --- | --- |
| 对话、Bot 读取的文件、图片与命令输出 | **你连接的模型服务** | 文件本体留在你的电脑上，但参与推理的内容会发给所选模型服务（私密会话同样如此）。处理敏感资料前，请确认认可对应服务商的数据条款。 |
| 网页搜索关键词 | **你连接的搜索服务** | 仅在 Bot 执行网页搜索时发送。 |
| 群聊普通消息 | **该群对应的会话上下文** | 平台允许 Bot 收到的普通群消息可能成为后续回复的参考；关闭“主动参与”只减少主动发言，仍会保留上下文。接入前请知会群成员。 |

## 使用第三方资料或技能时

网页正文、陌生附件和第三方仓库里可能藏着诱导 Bot 越权操作的指令（提示词注入）。

- 处理外来文档前先用副本测试；安装第三方技能前，先读清它的来源、`SKILL.md` 说明和附带脚本。
- 人格说明、技能和 `AGENTS.md` 都是“工作指导”，不能当作安全护栏——真正的权限边界要靠**电脑授权**和**系统账号/容器隔离**来守住。

## 任务做错了怎么办

按以下顺序止损（停止或收回权限只阻断后续操作，已改动的文件和已发出的消息需另行恢复或处理）：

1. 在会话中点击**停止**，等运行状态结束。
2. 查看执行记录里已跑过的命令、改过的文件和发出的消息，必要时从备份恢复。
3. 若任务来自聊天平台，先停用该平台账号阻断新消息（已有电脑任务仍需在会话内停止）。
4. 必要时收回 Bot 的电脑权限，或直接[断开这台电脑](/zh-cn/docs/computers/connect/#断开与停用电脑)。

## 保管账号、密钥与备份

- **Web 登录账号**可管理整个 Astral（包括私密会话），不要当作受限成员账号共享；远程访问务必按[登录与安全](/zh-cn/docs/hosting/security/)开启 HTTPS。
- **API Key、平台 Token、恢复码与接入命令**属于敏感凭据，截图求助或贴日志前先打码移除。
- **完整备份**包含聊天历史和恢复凭据所需的密钥，请按敏感文件妥善加密保存。
