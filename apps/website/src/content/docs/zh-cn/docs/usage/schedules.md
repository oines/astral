---
title: "计划任务"
description: "安排定时工作，或由本机程序的事件唤醒会话。"
---

计划任务会在约定时间把一段任务说明交给 Bot。例如，每天早上检查待办，或在周五整理本周记录。你可以在界面中创建，也可以在会话里让 Bot 帮你安排；两种方式都会出现在同一个任务列表。

安装 Astral 的主机需要在执行时保持运行。完全退出 Desktop 后，本机计划也会停止；错过的时间不会补执行。

## 创建计划

先在**设置 → 通用 → 时区**确认时间。所有计划共用这个时区；“跟随系统”采用安装 Astral 的主机时区，而不是浏览器或执行任务的电脑时区。

入口在当前 Bot 的侧栏**计划任务**。需要作出的主要选择是：用**使用指定会话**继续已有工作，还是用**每次新建会话**独立处理每一次任务。

**Prompt** 就是到点交给 Bot 的任务说明。写清资料在哪、需要做什么、结果放到哪里。例如，让已能使用工作电脑的 Bot 每天检查待办，可以写：

> 读取工作目录里的“待办.md”，列出今天到期且尚未完成的事项，在会话里汇报。保留原文件；如果文件不存在，告诉我需要提供什么。

创建后检查列表中的**下次**时间。一次性任务需要未来时间；普通重复任务可以直接选择每天或每周。

如果每次新建会话，任务会使用 Bot 当时的模型优先列表和默认电脑，不带入旧历史或聊天绑定。把必需的路径和要求写进任务说明里，避免依赖之前聊天里才出现的约定。这个模式不要求提前创建会话。

## 让 Bot 管理计划

也可以直接在会话中表达安排，例如：

> 每周五下午五点，在这个会话里整理本周尚未完成的事项。先确认 Astral 的时区，创建后告诉我下一次执行时间。

让 Bot 创建计划时，默认在当前会话执行。若要改用同一 Bot 下的其他会话，或每次执行时新建会话，需要明确告诉它。子代理会话不能作为计划目标。

操作后打开**计划任务**，确认条目、时间和任务正文，再按需要编辑或暂停。若创建时断线或结果不明确，先查看列表，避免重复创建。

## 事件唤醒

需要在外部程序发生变化时继续工作，可以让 Bot 注册事件唤醒端点，例如：

> 在 Minecraft 服务器所在电脑接入服务器消息，投递到这个会话。把监听脚本或配置路径、启动入口简要写在端点的维护备注里。

端点由 Bot 创建，随后出现在**计划任务 → 事件唤醒**。你可以查看、编辑名称、处理说明和维护备注，暂停或删除端点；页面的“添加任务”仍用于定时任务。普通根会话中的 Bot 可以注册和管理端点，子代理不能使用这些接口，也不能作为目标。

创建时省略目标就使用当前会话，也可以明确指定同一 Bot 下有权访问的其他根会话。端点的目标会话和接收电脑在创建后固定；切换当前会话或电脑不会改变它们。需要换目标时，让 Bot 创建新端点、更新调用方，再停用旧端点。

### 接入本机程序

打开端点详情，核对**接收电脑**和**目标会话**，复制投递地址或调用示例。外部程序必须在接收电脑上调用这个 localhost 地址；其他电脑可以管理端点，但不能投递。投递入口不要求凭据，Daemon 使用一个持久的本地端口，重启后不变。禁止通过反向代理、端口映射、隧道或 Webhook 转发服务把它暴露到公网；只供所属电脑的本机程序调用。普通 Computer API 的管理和发现请求仍使用当前命令凭据。

在接收电脑上，将下面的地址替换为端点详情中的投递地址：

```bash
curl --fail-with-body '<端点详情中的投递地址>' \
  -H 'Content-Type: application/json' \
  --data-raw '{"event_id":"build-1842","text":"构建失败，请检查日志并继续修复。"}'
```

每个新事件使用一个新的 `event_id`；重试同一事件时保留原 ID 和内容。去重收据保留 7 天：在此期间，相同 ID 返回原收据，不会重复唤醒，内容冲突会被拒绝。正文进入会话后，收据不再保留正文副本。请求也可附带结构化 `data`。`202` 表示已持久接收，并不等待模型处理完成；电脑与 Server 需要保持连接才能接受新投递。

**处理说明**告诉 Bot 收到这类事件后做什么；**维护备注**记录调用方位置，例如 `/opt/mc/listener.py，systemd: mc-events`。电脑来源由系统提供，不必在备注中重复。每批投递都会带上接收时保存的维护备注，便于 Bot 找到监听程序；它与处理说明分开呈现。修改备注只影响后续事件。

### 消息合并与临时屏蔽

消息按固定 1 秒窗口合并为一次投递。Agent 已在运行时，新事件作为后续上下文，在下一次模型请求时带入；当前生成不会被中途改写。

投递到同一会话的所有端点共用一个待投递缓冲，最多容纳 20 条或 4 KiB。此外，可以有一批已经交给会话、尚未被模型消费的事件，也独立受 20 条或 4 KiB 限制；无论有多少端点，最多保留这两批。每批内容预算包括消息正文，以及每个来源的一份端点名称、处理说明和备注；固定格式包装不计入。待投递缓冲达到容量时，系统将实际消息与流控说明放在同一次投递里，并临时屏蔽来源端点 60 秒。过长内容会明确标记截断；同一批中的每条事件保留独立边界、端点和来源电脑。Transcript 显示“事件唤醒”、端点名称及接收电脑，Bot 还会看到管理该端点的 Computer API 入口。

屏蔽期间的新调用返回 `429` 和 `Retry-After`，调用方应等待后再重试。被拒收的内容不会在恢复后集中回放，也不会不断触发模型。页面显示 60 秒临时屏蔽的到期时间；到期时若共享的待投递缓冲仍满，例如模型不可用、前一批尚未消费，新的调用会继续返回 `429`，直到会话处理事件、释放空间，不会无限排队。用户或 Bot 手动停用的端点保持停用。系统不会根据错误内容判断是否刷屏，也不额外调用模型做摘要。

## 到点后如何执行

使用指定会话时，会沿用那个会话届时的模型、电脑、权限和历史。会话空闲就开始工作；已经在忙时，任务会作为立即补充加入。计划消息带有时钟图标、**计划任务**标记和名称。

列表显示**已投递到会话**后，打开会话查看实际执行结果。每次新建模式可以从任务的**最近一次会话**进入。若想把结果发回外部聊天，需要在任务中写明发送要求，并检查聊天里是否收到。

一次性任务错过执行时间会显示**已错过**。重复任务会等到下一次未来时间，不补做停机期间漏掉的次数。

## 管理计划

在任务列表中可以编辑、暂停、恢复或删除。暂停和删除停止未来的投递；已经进入会话的任务仍需在会话中处理或停止。

使用指定会话的启用计划，只要还有下一次执行时间，就会让目标会话出现在侧栏**已计划**分组。每次新建模式的计划仍在任务页管理，生成的会话会出现在正在进行或最近列表中。

归档普通会话会保留其计划；永久删除会话或 Bot 会一起删除所属计划。复制或分叉会话不会复制计划。已过期的一次性任务要先改成未来时间，才能重新启用。

### 更改时区或设置复杂时间

已保存的一次性任务保持原来的实际执行时刻，更改时区只会改变显示时间。每天、每周等重复任务会按照新时区重新计算下一次时间。更改时区后，回到任务列表检查“下次”时间。

复杂安排可以使用五字段 Cron，依次是分钟、小时、日期、月份、星期。例如 `0 9 * * *` 表示每天 09:00，仍使用 Astral 的全局时区。普通的每天或每周安排，直接使用界面选项即可。

### 私密会话的计划

指向私密会话的计划对其他会话隐藏。由私密会话创建的“每次新建会话”计划也受来源会话保护，新会话会继承执行时来源会话的私密设置。你仍能在界面中管理这些计划。

## 计划没有按预期执行

- **下次时间不对**：检查全局时区和重复规则；浏览器所在时区不会自动覆盖 Astral 的设置。
- **显示已错过**：确认 Astral 主机是否在到点时运行。一次性任务改成未来时间后重新启用。
- **已经投递，但没有结果**：打开对应会话，检查模型错误、电脑离线或权限问题。
- **会话有结果，聊天平台没收到**：检查任务说明是否要求发送，以及会话中的实际发送结果。
- **编辑提示任务已变更**：重新打开最新条目，再应用需要的修改。
