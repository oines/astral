除了你主动发消息，Astral 还支持两种自动触发方式：
- **计划任务**：到点把一段任务说明交给 Bot（如每天早上汇总待办、每周五整理周报）。
- **事件唤醒**：让本机脚本或外部服务在发生变动时（如构建失败、服务告警）主动唤醒指定会话继续处理。

:::note[主机需要在线]
安装 Astral 的主机在触发时刻必须保持运行（完全退出 Desktop 会停止本地计划，错过的时间不会补执行）。
:::

## 创建定时计划任务

开始前先在 **设置 → 通用 → 时区** 确认时区（所有计划共用这个时区，“跟随系统”指安装 Astral 的主机时区）。

### 方式一：在界面创建

打开当前 Bot 侧栏的 **计划任务**，做两个关键选择：
1. **执行目标**：**使用指定会话**（延续已有上下文）还是 **每次新建会话**（每次独立执行，用 Bot 当时的模型优先列表与默认电脑，需在 Prompt 里写齐路径与要求）。
2. **Prompt**（任务说明）与时间：普通每日/每周直接点选，复杂规则支持五字段 Cron（分 时 日 月 周，如 `0 9 * * *`）。示例：

> 读取工作目录里的“待办.md”，列出今天到期且未完成的事项，在会话里汇报。保留原文件；若文件不存在，告诉我需要提供什么。

保存后核对列表中的**下次**时间。

### 方式二：直接在会话里让 Bot 帮你安排

> 每周五下午五点，在这个会话里整理本周尚未完成的事项。先确认 Astral 的时区，创建后告诉我下一次执行时间。

Bot 默认在当前会话创建（需要指定其他会话或每次新建会话时明确告诉它；子代理会话不能作为目标）。建好后打开**计划任务**核对时间与正文即可。

## 用本机程序触发：事件唤醒

需要外部程序在出状况或收到消息时叫醒 Bot，可以在普通根会话里请 Bot 注册一个**事件唤醒端点**：

> 在运行构建服务的电脑上接入构建失败通知，投递到这个会话，并把监听脚本路径和启动入口记在端点的维护备注里。

端点建好后会出现在 **计划任务 → 事件唤醒**，你可以随时编辑名称、处理说明和维护备注，或者暂停、删除。（端点的接收电脑和目标会话创建后固定，换目标请建新端点并停用旧端点。）

### 接入本机程序

打开端点详情，核对**接收电脑**和**目标会话**，复制投递地址。在**接收电脑**上用本机程序调用这个 `localhost` 地址：

```bash
curl --fail-with-body '<端点详情中的投递地址>' \
  -H 'Content-Type: application/json' \
  --data-raw '{"event_id":"build-1842","text":"构建失败，请检查日志并继续修复。"}'
```

:::caution[仅限本机调用，切勿暴露公网]
事件投递入口使用 Daemon 的持久本地端口且不要求凭据，**严禁**通过反向代理、端口映射、隧道或 Webhook 转发暴露到公网——只供接收电脑上的本机程序调用。
:::

调用要点：
- **幂等去重**：每条新事件传唯一的 `event_id`；重试同一事件保留原 ID 和内容（去重收据保留 7 天，重复 ID 不重复唤醒，内容冲突会被拒）。
- **结构化数据与响应**：可附加 JSON `data` 字段；返回 `202` 表示已持久接收（不等待模型跑完），接收期间电脑与 Server 需在线。
- **处理说明 vs 维护备注**：**处理说明**写收到事件后怎么处理；**维护备注**记监听脚本或服务入口（如 `/opt/mc/listener.py, systemd: mc-events`），每批投递都会附带，方便 Bot 自行定位和维护。

### 消息合并与临时屏蔽

短时间内到达的事件会按 1 秒窗口合并为一次投递；如果 Agent 正在运行，新事件会作为后续上下文在下一次模型请求时带入，不会中途改写正在生成的回复。

<details class="astral-doc-details">
<summary>查看缓冲上限、60 秒临时屏蔽与 429 重试细则</summary>

投递到同一会话的所有端点共用一个待投递缓冲，最多容纳 20 条或 4 KiB。此外，可以有一批已经交给会话、尚未被模型消费的事件，也独立受 20 条或 4 KiB 限制；无论有多少端点，最多保留这两批。每批内容预算包括消息正文，以及每个来源的一份端点名称、处理说明和备注；固定格式包装不计入。待投递缓冲达到容量时，系统将实际消息与流控说明放在同一次投递里，并临时屏蔽来源端点 60 秒。过长内容会明确标记截断；同一批中的每条事件保留独立边界、端点和来源电脑。Transcript 显示“事件唤醒”、端点名称及接收电脑，Bot 还会看到管理该端点的 Computer API 入口。

屏蔽期间的新调用返回 `429` 和 `Retry-After`，调用方应等待后再重试。被拒收的内容不会在恢复后集中回放，也不会不断触发模型。页面显示 60 秒临时屏蔽的到期时间；到期时若共享的待投递缓冲仍满，例如模型不可用、前一批尚未消费，新的调用会继续返回 `429`，直到会话处理事件、释放空间，不会无限排队。用户或 Bot 手动停用的端点保持停用。系统不会根据错误内容判断是否刷屏，也不额外调用模型做摘要。

</details>

## 到点执行与日常管理

- **侧栏标记**：挂有固定会话定时任务或事件端点的会话会进入侧栏**已计划**分组（时钟代表定时，闪电代表事件唤醒；正在执行或子代理运行中会进入**进行中**分组并保留标记）。点会话的三个点菜单可直达对应任务编辑。
- **状态核对**：列表显示**已投递到会话**后，点进会话检查实际结果（想发回微信/Telegram 等外部聊天，记得在 Prompt 里写明发送要求）。
- **暂停、归档与时区变动**：
  - 暂停或删除只阻止未来投递；已进会话的任务需在会话里停止。
  - 归档会话会停用其计划和事件端点，恢复会话后需手动重新启用；永久删除会话或 Bot 会一并删除所属计划。
  - 更改时区时，一次性任务保持原绝对时刻（仅显示变化），重复任务按新时区重算下次时间。
  - 指向私密会话的计划（以及私密会话创建的“每次新建会话”计划）会对其他会话隐藏并继承私密设置。

## 计划没按预期执行？

| 现象 | 排查什么 |
| --- | --- |
| 下次时间不对 | 检查**设置 → 通用 → 时区**与重复规则（浏览器时区不会覆盖全局设置）。 |
| 显示**已错过** | 检查到点时 Astral 主机是否运行；一次性任务改未来时间后重新启用。 |
| 已投递但没结果 | 打开目标会话，检查模型报错、电脑离线或权限问题。 |
| 会话有结果，聊天软件没收到 | 检查 Prompt 是否写明发回聊天，并核对发送工具执行结果。 |
| 编辑提示任务已变更 | 重新打开最新条目后再保存修改。 |
