---
title: "计划任务"
description: "按一次性时间或重复规则，向指定会话投递一段 prompt。"
---

在侧栏打开**计划任务**，管理当前 Bot 的计划。可以手动添加，也可以让 Bot 通过 Gateway API 创建。两种方式使用同一个任务列表，都支持编辑、暂停、恢复和删除。

## 创建计划

填写名称，选择执行方式和要投递的 prompt。**使用指定会话**会继续已有上下文；**每次新建会话**会为每个执行时刻创建独立会话，使用 Bot 当时的默认模型和电脑，不复制旧历史或 IM 绑定。即使还没有会话，也可以创建后一种计划；任务列表会提供最近一次创建的会话入口。

可以指定一次性的日期与时间，也可以每天、每周重复，或使用自定义五字段 Cron 表达式。所有计划统一采用**设置 → 通用 → 时区**中的全局时区，默认跟随 Astral 安装主机的操作系统，不跟随浏览器设备或所选电脑。也可以选择 `Asia/Singapore` 等 IANA 时区；每个任务不再单独设置时区。

一次性计划输入的日期与时间按全局时区解释。保存后，更改时区只改变它的显示时间，不改变已经确定的执行时刻。重复计划则采用新的全局时区，重新计算下一个未来执行时刻。

指定的已有会话必须属于同一个 Bot。投递时使用该会话当前的上下文、模型、电脑和权限。一个会话可以有多个计划；复制或 Fork 会话不会复制计划。

指向私密会话的计划对其他会话的 Gateway 调用隐藏。私密会话创建的**每次新建会话**计划同样受到来源会话的私密权限保护，执行时创建的会话继承来源当时的私密设置。你仍能在界面中管理所有计划。

## 到点后如何执行

会话空闲时直接启动工作；会话忙碌时，通过**立即补充（Steer）**在下一个可接收输入的边界加入 prompt。气泡显示在右侧，并带有时钟、**计划任务**和任务名称，便于与手动消息区分。

**已投递**表示会话已收到任务。打开对应会话查看执行进度和结果；需要发回外部聊天时，在任务中写明发送要求。

管理这些计划的主机需要保持 Astral 运行。完全退出 Desktop App 会停止本机调度。错过的时刻全部跳过：一次性任务标记为**已错过**，重复任务从下一个未来时刻继续，不补执行。

## 管理计划

使用固定会话、任务启用且存在下一次执行时间时，目标会话进入侧栏的**已计划**分组。每次新建模式的计划在任务页管理，创建出的会话进入**正在进行**或**最近**。每个会话只出现一次。暂停和已结束的任务仍保留在计划任务页面。

暂停或删除会阻止后续投递，已被会话接受的输入仍保留在队列中。想再次启用已过期的一次性计划，需要先设置新的未来时间。归档普通会话不会暂停计划；永久删除会话或 Bot 会清理所属计划。

## 让 Bot 管理计划

Bot 可以通过电脑上的认证 Gateway 发现 `schedules` 能力，为当前会话或同 Bot 的其他会话创建计划。例如每天按 Astral 全局时区的 09:00 执行一次：

```json
{
  "session_id": "<session-id>",
  "session_mode": "existing",
  "title": "每日项目检查",
  "prompt": "检查今天的项目动态，汇报需要关注的问题。",
  "enabled": true,
  "timing": {
    "kind": "cron",
    "cron": "0 9 * * *"
  }
}
```

通过 API 创建一次性计划时，使用 `timing.kind: "once"`，并为 `timing.at` 提供含明确偏移或 `Z` 的绝对 RFC3339 时间。API 不提供 `timing.timezone` 字段。

每次新建模式使用 `session_mode: "new"`，不传 `session_id`；`last_session_id` 标识最近一次实际创建的会话。`/v1/schedules` 提供列表、读取、创建、修改和删除接口。修改需要提交完整的可编辑配置及当前版本号；删除也需要版本号。发生冲突时，应先读取最新任务再修改。创建过程中连接中断可能导致结果无法确认，应先核对任务列表，再决定是否重新创建。
