Astral 使用你提供的模型服务。模型连接由 Server 发起，因此服务地址、API 凭据和网络连通性都应以 Server 所在机器为准。

## 添加模型服务

1. 打开 **设置 → 模型**查看已配置连接，再添加服务；预置服务在添加连接时选择。
2. 选择对应服务或兼容接口，填写地址和所需凭据。
3. 点击当前区域的“保存连接”并获取模型目录。获取失败会保留已保存连接，可直接重试，也可以手工添加明确的模型 ID。
4. 在模型列表中确认要使用的模型，按实际能力配置推理等选项。

服务地址可达不代表模型有使用权限。若调用失败，分别检查 API Key、模型 ID、服务额度以及服务返回的错误。不要把浏览器能打开某个地址当成 Server 能访问它的证明。

## 刷新或移除模型

进入某个服务商的模型列表，点击 **刷新模型目录**，以这条连接返回的完整目录同步模型。新列出的模型会加入；不再列出的模型会移除，包括手工添加或修改过的模型。成功返回空目录会清空当前模型列表；获取失败或目录不完整时保留上次列表。

Codex 和 GitHub Copilot 也遵守这些规则，以已登录账号返回的模型目录为准。

你修改过的模型只要仍在目录中，整份已保存配置就会保留，包括推荐资料、显示名称、协议、限制和启停状态。没有修改过的模型则更新目录资料。模型编辑中仍可将单个字段恢复为已保存的推荐值；这个操作不会联网刷新目录。

查找公开模型资料时，Astral 先精确匹配模型 ID 最后一个 `/` 后的完整名称；没有精确结果时，才忽略字母大小写补查。日期、版本和后缀仍须一致，发给服务商的模型 ID 保持原值。多个来源可以逐字段补充资料；当前连接资料优先，公开记录仍按原有来源优先级合并，同一优先级的字段冲突保持未知。

删除单个模型后，如果服务商目录仍列出它，下次刷新会重新加入。删除服务商会移除这条连接及其当前模型。重新创建同名连接会产生独立的新连接，不接管之前的模型选择。

## 选择使用范围

在 **设置 → Bot → 目标 Bot → 基本设置**选择默认模型。它用于新会话；已有会话可在输入区单独选择模型和可用的推理选项。

不同服务对推理参数和工具调用的支持不同，以该模型显示的选项和实际响应为准。

编辑器只提供当前接口格式能够表达的推理选项。某个开关不可用，不代表接口默认或其他可用选项有错。目录缺少上下文或最大输出限制时，推理选项仍可查看；保存供 Bot 使用的模型前，需要补全这些限制。

更换模型 ID 或接口格式时，Astral 会移除属于旧模型或旧接口的目录资料，保留为新选择取得的资料。你明确填写的设置继续保留在草稿中，并在保存前校验；如果之前的默认推理不再适用，需要重新选择支持的选项。

所选连接或模型被移除、停用，或配置待补全时，Astral 会显示不可用状态，并保留选择其他可用模型的入口。已有会话历史仍可打开，无需先修复旧连接才能换模型。修改 Bot 默认模型只影响新会话；已有会话保留自己的选择。已经发出的请求及其重试继续使用发起时冻结的配置。后续模型请求使用新选择；请求准备至冻结和上下文压缩期间暂时不能切换。

模型编辑中可直接选择默认推理。会话可以继承模型默认、使用接口默认，或选择接口支持的原生档位、开关与预算。能力声明与默认调用设置分别表达；模型资料来自当前连接、models.dev 和用户明确配置，缺失资料保持未知。切换服务商只在本次请求省略不能复用的签名或私有推理，保留原始历史和工具关系。历史位置 Fork 继承该位置的模型选择，创建不依赖旧模型可用。

## 配置网页搜索

网页搜索是独立连接，不会因模型 API 配置成功而自动可用。

1. 打开 **设置 → 搜索**，选择搜索服务并填写连接信息。
2. 保存连接后，使用测试查询检查结果。
3. 到 Bot 的基本设置中选择该搜索服务。

修改测试区的查询不会改变 Bot 的配置；测试使用已保存的连接。自托管搜索地址同样需要从 Server 可达。

## 群聊的主动参与模型

开启[群聊主动参与](/zh-cn/docs/chat/groups/)后，Astral 会判断普通群消息是否需要唤醒空闲的 Bot。默认跟随会话模型，也可以为 Bot 指定单独的判断模型。Bot 工作时，由主模型直接读取新增聊天上下文，不再单独判断。参与判断模型只决定是否唤醒 Bot，不代替主模型执行任务。
