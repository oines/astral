要让 Bot 回复和执行任务，先给 Astral 连接一个模型服务，再选择具体模型。模型服务提供计算能力；Astral 使用你连接的账号或 API Key 发起请求。

首次设置中的“模型”步骤与**设置 → 模型**使用同一套连接界面。完成连接后仍要选定一个可用模型，才能继续设置电脑。

## 先准备服务账号

从你打算使用的模型服务开始。打开该服务商的官方网站，登录或创建账号，并确认这个账号允许使用所需模型、还有可用额度。聊天产品的订阅是否包含这里需要的调用权限，要以服务商说明为准。

在 Astral 添加服务时，可以看到它需要哪种连接方式：

| 界面要求 | 你需要准备什么 |
| --- | --- |
| **API Key** | 在对应服务商的开发者平台或控制台找到 API 密钥管理，创建密钥，再复制到 Astral。若表单提供**获取 API Key**链接，可以从那里打开对应页面。API Key 是调用密钥，不是账号密码。 |
| **继续登录／连接账号** | 按界面打开服务商登录页，使用显示的验证码完成授权。此类连接使用登录账号的权限和模型列表。 |
| 自定义服务地址 | 从服务管理员或服务文档取得 Base URL、接口协议和所需密钥，适用于自己的模型服务或兼容接口。 |

API Key 只填入连接表单，不需要发到聊天中。你发送的任务、Bot 读取的资料和工具结果会交给所选模型服务处理；详情见[数据去向](/zh-cn/docs/start/safe-use/#我的资料会发送到哪里)。

## 添加模型服务

入口是**设置 → 模型**中的**添加**。选择与你账号对应的预置服务后，通常可以沿用预填的 Base URL（API 地址）和协议；有区域选项时，要与账号和密钥的服务区域匹配。

密钥连接默认勾选**保存后自动导入模型**，保存后查看可用模型列表。账号登录连接则在完成授权后读取账号目录。首次使用先选一个已启用、没有配置缺失提示的模型即可。

如果没有对应预置，选择**自定义服务商**。按服务方给出的资料填写地址、协议和密钥；额外请求头、推理参数映射等高级选项，仅在服务文档明确要求时设置。

模型连接由 Astral 的后台服务（Server）发起。使用 Desktop 时，通常就是安装 Desktop 的电脑；使用独立 Server 时，是部署 Server 的机器。自定义地址必须能从这台机器访问。

### 没有导入想要的模型

先点击**刷新模型目录**，并检查页面错误。如果服务本身不提供模型目录，或你需要手动配置，在列表中点击添加模型，填写服务方提供的**完整模型 ID**。模型 ID 是 API 使用的名称，不一定等于网页上的展示名称。

Astral 会尽量从当前连接和公开模型资料中补全参数。已有推荐值时可以直接使用；缺失时，按服务商对这个模型的说明填写：

- **上下文窗口**：一次请求能够容纳的内容范围，包括对话、资料和输出，单位为 Token。
- **最大输出 Token**：一次回复允许生成的上限。

Token 是模型计算文本和其他输入大小的单位，不等同于字数。不要根据表单示例随意填写限制，也不要用另一个同名模型的参数替代当前服务的说明。补全并保存后，模型才会成为可选项。

## 为 Bot 或会话选择模型

首次设置时，在模型步骤选中刚配置的模型，然后继续电脑步骤。已经进入主界面时，打开**设置 → Bot → 目标 Bot → 基本设置**，选择默认模型；它只影响新会话。已有会话在输入区单独选择模型。

选定一台在线电脑后，发一个可以核对的小任务：

> 请读取当前电脑的工作目录，列出其中的文件名，不修改任何文件。然后告诉我你使用的电脑和目录。

查看 Bot 是否实际执行读取并返回结果。能选中模型表示配置已经齐全；实际任务可以进一步检查密钥、额度和工具调用是否可用，调用可能产生服务费用。

如果模型明确配置为不支持图片，请求会用文字标记替代图片，让模型继续处理文字内容。需要识别图片时，选择支持图片的模型。历史原图仍会保留，切换到支持图片的模型后，新的请求可以继续使用原图。

在会话输入区更换模型或推理设置，也会同步覆盖它当前已有的全部子代理，包括更深层的子代理和之前单独选过其他模型的子代理。已经发出的请求按原选择完成，后续请求使用新选择；其他会话和普通独立分支保留各自的设置。查看子代理过程，以及之后新建子代理如何选择模型，见[后台委派](/zh-cn/docs/usage/conversations/#把耗时工作交给子代理)。准备请求或总结长会话时，选择控件可能暂时不可用。如果旧模型被停用或移除，直接选择另一个可用模型，已有历史仍然保留。

## 配置网页搜索

想让 Bot 主动搜索网页时，再添加搜索服务。它与模型连接分别配置，模型 API Key 不会自动成为搜索服务的密钥。

在**设置 → 网页搜索**添加服务。需要密钥时，到该搜索服务的平台取得；自托管服务使用自己的地址。保存连接后，用简单查询（例如“Astral GitHub”）检查返回的标题和链接，再到 Bot 的**基本设置**选择这条连接。

测试使用已保存的连接，测试查询不会成为 Bot 的固定任务。每个 Bot 使用一个选定的搜索服务；服务没有配置或调用失败时，需要处理该连接，Astral 不会自动换用另一个服务。自托管搜索地址也必须从 Server 所在机器访问得到。

## 常见问题

| 看到的情况 | 下一步 |
| --- | --- |
| 保存了服务，但首次设置仍不能继续 | 回到模型列表，确认至少一个模型已启用、限制已补全，再在引导中选中它。 |
| 提示密钥无效或没有权限 | 确认 Key 来自当前服务和区域，并在服务商平台检查该账号是否能使用这个模型。账号登录方式可以重新连接账号。 |
| 提示额度不足或限流 | 到服务商平台查看额度和调用限制，再决定是否充值、等待或换用已配置的其他模型。 |
| 连接超时或地址不可达 | 检查 Server 所在机器的网络，以及 Base URL；浏览器能打开服务商网站不能代替这项检查。 |
| 能回复文字，但执行任务时报工具相关错误 | 检查该服务的模型是否支持工具调用，以及选择的协议是否匹配。必要时换用支持该能力的模型。 |
| 搜索测试有结果，Bot 却不能搜索 | 确认在这个 Bot 的基本设置中选择了刚测试的搜索服务。 |

## 调整推理选项

先沿用模型默认设置，能完成任务后再按需要调整。支持推理选项的模型，可以在模型编辑中设置默认方式；会话也可以单独选择支持的档位或预算。

**继承模型默认**使用你在模型配置里保存的选择；**接口默认**让服务按自身默认方式处理；其他档位以当前模型实际提供的选项为准。更换模型 ID 或接口协议后，重新检查这些选项是否适用，修正提示的问题后再保存。

某个子任务需要不同模型时，在原会话里告诉 Bot，并说明子代理名称。Bot 可以为新建或已有子代理选择另一个可用模型及其支持的推理设置。子代理运行出错时，上级会收到通知，可按原因决定更换模型或重试；单独更换模型不会启动新一轮工作。只指定模型、没有单独指定推理设置时，使用该模型已保存的默认值；接口默认需要明确选择。单独调整某个子代理不影响它的下级，而原会话输入区的切换会覆盖全部已有子代理，详见[后台委派](/zh-cn/docs/usage/conversations/#把耗时工作交给子代理)。

## 刷新或移除模型

**刷新模型目录**会使 Astral 的列表与该连接当前返回的列表同步。新模型会加入，不再列出的模型会移除，包括手工添加的模型。仍在目录中的模型会保留你的修改；未手动修改的参数会采用新的推荐资料。

刷新失败或目录不完整时保留旧列表；如果服务成功返回空目录，当前列表会清空。Codex 和 GitHub Copilot 的目录来自已登录账号。

删除单个模型后，下次刷新仍可能重新加入它。删除服务商会同时移除其模型。重新添加同名连接后，要为受影响的 Bot 和会话重新选择模型，历史记录保留。

## 群聊的主动参与模型

开启[群聊主动参与](/zh-cn/docs/chat/groups/)时，Astral 会判断普通群消息是否值得唤醒空闲的 Bot。默认使用会话模型，也可以在 Bot 设置中为这项判断单独选模型。

判断模型只决定是否开始工作。Bot 开始后，仍由会话模型执行任务，并直接处理工作期间收到的聊天内容。
