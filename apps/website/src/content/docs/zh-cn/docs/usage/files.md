你可以上传资料让 Bot 处理，也可以让它直接使用已连接电脑上的文件。文件放在哪台电脑，由会话选择的电脑决定；打开 Astral 的浏览器只是操作入口。

例如，你在笔记本的浏览器里打开 Astral，却在会话中选了“办公室电脑”，上传的资料和生成的结果就会保存在办公室电脑上。Bot 读取的内容可能发送给所选模型服务，提供资料前可查看[数据去向](/zh-cn/docs/start/safe-use/#我的资料会发送到哪里)。

## 给 Bot 提供文件

上传附件前确认会话当前选择的电脑，文件会传到那里。任务里说明要处理哪份资料、希望得到什么，以及是否保留原文件。例如：

> 根据我上传的会议记录，整理一份待办事项，包含负责人和截止日期。没有明确写出的信息标为“待确认”。保留原文件，另存为“会议待办.md”，给我下载链接。

如果资料已经在电脑上，可以直接提供完整路径，例如“读取办公室电脑上的 `/home/mei/reports/meeting.txt`”。路径必须属于 Bot 正在使用的电脑。拿不准位置时，让 Bot 先列出当前目录和文件名，再开始处理。

Windows 上可提供原生路径，例如 `C:\Users\mei\reports\meeting.txt`。所选电脑运行 Windows 时，文件工具也兼容 `/c/Users/mei/...`、`/mnt/c/Users/mei/...`、`/cygdrive/c/Users/mei/...` 这些盘符写法。路径始终由所选电脑按自己的操作系统解释。

内置文件工具单次读取或写入的内容上限为 32 MiB。处理更大的文件时，可以让 Bot 使用命令读取或修改所需部分。这个限制与附件上传、下载的大小限制分开。

## 打开结果

点击会话中的图片，会打开全屏查看器，可以缩放和下载；普通文件直接在右侧预览中打开。文件和子代理对话各有自己的标签，可以来回切换，不用重新寻找消息里的入口。能否预览取决于文件类型。需要长期保存或交给别人时，下载一份到自己的设备，或在来源电脑上另行备份。

Markdown 使用阅读视图。代码、配置、日志及其他能够识别为文本的文件使用代码或纯文本预览，也包括未知扩展名和没有扩展名的文件。预览工具栏中的**复制内容**可复制文本，Markdown 复制的是原文。大文件只加载了一部分时，**复制预览内容**只复制当前片段；需要完整内容时可下载文件。

右侧工作区通常与聊天并排，各占独立空间，可以拖动两者之间的分隔线调整宽度。可用宽度减小时先收窄右栏，只有实际空间不足以同时容纳两栏时才覆盖聊天。

右栏顶部固定的**文件**按钮用于展开或收起预览右侧的文件管理器，两种状态下位置不变。拖动预览与文件管理器之间的分隔线，可以调整它们的宽度；右栏较窄时，文件管理器以覆盖预览的抽屉打开。点击文件行即可预览，右键菜单可下载文件或复制路径。

无需先打开附件，也可以直接用**文件**浏览当前会话电脑的工作目录；还没打开文件时，目录跟随会话电脑切换。打开文件后，目录定位到它的来源电脑和所在位置；切换文件标签时，目录随当前文件切换电脑和位置。切换会话电脑不会关闭或改变已有文件标签的来源，已经收起的文件管理器也保持收起。浏览目录或打开文件不会改变 Bot 执行任务所用的电脑和工作目录。

子代理标签只读展示完整对话和工具过程。需要补充任务或修改要求时，回到原会话告诉 Bot。

如果回复只说“已完成”却没有文件链接，可以接着要求：

> 请给我生成文件的链接，并写出来源电脑和完整保存路径。

文件链接会记住原来的电脑。之后切换会话电脑，旧链接仍指向原文件；文件不会随之搬家。

工作文件更新后，可以用**刷新预览**重新读取，无需关闭标签。文件管理器中的刷新只更新目录列表。

在 Desktop 中，文件来源确实是当前应用管理的本机电脑时，可以通过右键菜单在访达、文件资源管理器或系统文件管理器中定位文件；目录的对应操作会直接打开该目录。远程和容器文件可以在 Astral 中浏览、预览和下载，不会作为自己设备上的路径打开。浏览器界面不提供系统文件管理器操作。

有些链接指向为历史保留的快照。预览、下载和系统文件定位使用的是该快照在来源电脑上的实际位置。需要处理当前工作文件时，让 Bot 提供原文件路径。

Bot 读取电脑上的图片时，默认保留原始尺寸。发送给模型的编码数据超过默认 150KB 压缩阈值时，使用质量 75 的 WebP；较小的图片保留原始字节。最终大小随图片内容变化，电脑上的原文件保持原样。

工具直接返回的图片保存在会话历史中，重新打开历史时仍可查看；显示这些图片无需在电脑上额外保存一份副本。

### 文件打不开

按以下顺序检查：

1. 在**设置 → 电脑**确认来源电脑在线。
2. 在 Bot 的**电脑权限**中确认它仍能使用这台电脑。
3. 让 Bot 检查原路径上的文件是否还存在、是否可以读取。被移动或删除的原文件需要重新找到，或从备份恢复。

历史消息里看得到文件链接，并不保证原文件仍然存在。重要结果应另行保存。

## 工作目录和共享范围

工作目录是 Bot 执行任务时默认使用的文件夹。想知道当前位置，可以直接问：“你当前使用哪台电脑、哪个工作目录？”要整理多个项目，可要求它切换到指定项目目录后再操作，并确认完整路径。

同一个 Bot 在同一台电脑上的不同会话，可能使用同一个默认工作目录。因此，新建会话并不会自动分出一套独立文件。给不同项目明确命名目录，可以避免把资料混在一起。

目录用于整理文件，访问权限由运行电脑服务的系统账号决定。Bot 可能读写该账号有权访问的其他位置。需要限制文件访问时，使用独立系统账号或[容器电脑](/zh-cn/docs/computers/containers/)。

## 从聊天接收和发送文件

在 Telegram、QQ 等已接入的聊天中，可以把附件和任务一起发给 Bot。聊天图片使用更轻量的预览：编码数据的压缩阈值为 30KB，WebP 质量为 30，默认保留原始尺寸。这些参数用于控制压缩，不保证每张图片都输出为固定大小。预览在收到时准备，后续对话直接复用；需要准确辨认小字或检查细节时，要求它“下载原图后再读取”。下载会保留原始图片文件。视频和普通文件按任务需要下载到电脑。

需要把成果发回聊天时，写明发送要求，例如：

> 把整理好的“会议待办.md”作为附件发回当前聊天。

然后检查聊天中是否实际收到附件。平台支持的格式、大小和账号权限可能影响发送；只有在 Astral 中生成文件或展示路径，还没有完成平台附件发送。

如果图片提示暂不可用，可以让 Bot 重新下载原图，或再次上传文件。需要备份整个 Astral 时，请分别保留 Server 数据、电脑工作文件和容器数据，步骤见[升级与备份](/zh-cn/docs/hosting/maintenance/)。
