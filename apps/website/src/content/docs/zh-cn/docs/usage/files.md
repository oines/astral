---
title: "文件与结果"
description: "上传资料、打开生成的文件，并理解文件保存的位置。"
---

工作文件保存在执行任务的电脑上。会话中的文件链接记住来源，因此切换电脑后仍指向原来的文件。

## 给 Bot 提供文件

在会话中选择电脑，再使用附件按钮上传资料。上传目标是这台电脑，不是官网或浏览器所在设备。也可以直接告诉 Bot 已连接电脑上的绝对文件路径。

让 Bot 先确认文件名、位置和任务要求，尤其是多个电脑都有相似目录时。

## 打开结果

Bot 返回文件链接后，可以打开预览或下载。图片可在会话中显示；其他格式是否能直接预览取决于文件类型。

读取原始内容需要来源电脑在线，且 Bot 仍有相应访问权限。保留会话历史不等于文件已经备份到了 Server。

## 工作目录和共享范围

同一个 Bot 在同一台电脑上有一个默认工作目录，不同会话可能使用这个共同目录。需要隔离项目文件时，明确使用不同项目目录或容器。

默认工作目录不是文件系统沙箱。Bot 能访问的范围取决于电脑服务账号的权限，而不只限于当前目录。

## 从聊天接收和发送文件

平台附件会保留来源信息，Bot 可在需要时读取或下载到电脑上。能否发送某种文件，还取决于平台权限、格式与限制。

新收到的 IM 图片进入 Bot 的旁观上下文前，会等比生成最多 75,000 总像素的预览，并标记图片已压缩，同时保留原图引用。文字或细节不清楚时，Bot 可以下载原图，再使用现有文件工具读取。群聊参与判断、普通请求和后续上下文压缩使用同一份已保存预览。已有历史和通过文件工具读取的图片保持原样。

QQ（NapCat 和官方 Bot）、Telegram、微信及飞书的图片预览下载或解码失败时，消息仍保留文字、引用和附件来源，并标明预览不可用。后续消息会继续接收，不会被这张图片阻塞。图片类型文件也遵循相同规则；原件不会因此自动保存，Bot 可按需主动重试下载。

文件出现在 Astral 会话中，不代表已经发到 Telegram、QQ、微信或飞书。可以明确要求“把生成的文件发回当前聊天”，再查看发送结果。

备份时要分别保存 Server 数据、电脑工作文件和容器数据，见[升级与备份](/zh-cn/docs/hosting/maintenance/)。
