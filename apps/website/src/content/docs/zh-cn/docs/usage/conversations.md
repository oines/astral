---
title: "使用会话"
description: "发起任务、补充要求、停止执行，并继续已有工作。"
---

一个会话属于一个 Bot，保存消息、执行记录和任务上下文。可以从侧栏重新打开已有会话，继续之前的工作。

侧栏优先显示正在进行和已计划的会话，其次按 Telegram、QQ、微信、飞书组织绑定 IM 的会话，最后是普通会话的固定与最近分组。空组不显示，QQ 官方 Bot 与 NapCat 同属 QQ 分组；每个会话按此优先级只出现一次。

普通会话可以通过菜单重命名、归档或恢复；Bot 也可以通过 Gateway API 修改自己会话的标题和归档状态。绑定 IM 的会话使用聊天名称，不允许重命名或归档，菜单会隐藏这两个动作。要安排未来投递的 prompt，参阅[计划任务](/zh-cn/docs/usage/schedules/)。

## 发起任务

选择 Bot，新建会话，确认输入区域中的模型和电脑，然后发送任务。把希望得到的结果、需要使用的文件和重要限制说清楚。

电脑决定命令和文件操作在哪里执行。模型决定如何理解和推进任务。两者可以在会话中调整，无需为了换电脑另开一个会话。

## 私密会话

在侧栏会话菜单中选择**设为私密**，会话旁会出现锁标记；选择**取消私密**可以恢复。你仍能通过 Desktop 和浏览器正常打开、管理它。

其他会话即使属于同一个 Bot，也不能通过 Gateway API 发现、读取或修改私密会话。它绑定的 IM 聊天和指向它的计划任务同样隐藏，平台账号设置为允许全部聊天也不能绕过。私密会话仍能访问自己的资源；Fork 创建的会话继承来源会话的私密设置。

聊天的私密状态跟随当前会话绑定，解绑或换绑后按新的关系判断。已知 ID 和旧分页游标也会重新检查权限。此功能控制后续 Gateway 访问，不会删除已经复制进其他会话的信息，也不隔离共享电脑上的文件。

## 任务运行时补充消息

普通会话支持两种方式：

- **排队：** 当前一轮结束后再处理补充消息。适合下一步任务。
- **立即补充：** 尽快把新要求交给当前运行中的 Bot，在可处理输入的边界生效。适合纠正方向或新增限制。

尚未处理的排队消息可以编辑、删除或调整顺序。已经开始执行的操作不会因为补充一句话自动撤销。

接入聊天平台的会话中，Bot 工作时收到的聊天消息会进入后续模型步骤，无需另一次唤醒。空闲时，私聊、直接提及、回复 Bot 及平台支持的戳 Bot 会直接唤醒它；普通群消息遵循[主动参与设置](/zh-cn/docs/chat/groups/)。绑定会话中的 Web 输入仍使用立即补充方式。

## 停止与继续

点击停止后，等待状态确认。停止不会回滚已经修改的文件或已完成的外部操作；必要时检查执行记录和实际结果。

会话显示“继续”时，可以从已有上下文继续执行，也可以先发送新的说明。来源电脑离线或模型连接失效时，先恢复依赖再继续。

## 时区

在**设置 → 通用 → 时区**中选择当前 Astral 部署共享的时区。**跟随系统**采用 Astral 安装主机的操作系统环境，不是浏览器设备或执行命令的电脑。消息时间、回复日期和计划调度在各客户端统一使用此设置；今天、昨天也按该时区判断，悬停回复时间可以查看包含日期、秒和时区的完整时间。

更改时区会更新界面的日期显示，但不会改变事件实际发生的时刻。只有新构造的模型输入使用新的时区；此前的模型上下文、环境快照、摘要和冻结请求不会重写，网络重试继续使用原始请求。

模型的 System Prompt 提供当前 Bot 与会话身份；新环境快照只承载电脑、工作区、可用技能和 API 发现等环境信息。分叉会话使用自己的会话 ID，复制过来的历史保持原样。

## 长会话

聊天先加载近期消息，向上接近顶部时继续加载较早历史；重连保留已加载的消息和阅读位置。本次打开期间切回仍在缓存中的会话，也会恢复已加载的历史和阅读位置，再同步新消息；刷新页面或缓存被淘汰后重新加载近期消息。

执行步骤的参数、文本输出和结果随消息页一起加载，点击展开即可查看。图片和附件仍按需读取；原始 Rollout 可通过**导出 Rollout**获取。Bot 输出时向上滚动会停止跟随，滚回底部或点击“回到最新”后恢复。

会话变长时，Astral 会总结较早的上下文，并为后续模型请求保留近期消息。即使 Bot 一直保持沉默，收到的聊天消息和图片也会计入上下文预算。预算在适用范围内采用模型已报告的真实用量，再加上此后所有新增内容的估算。

自动总结可能调用模型生成摘要，但不会因此启动普通任务或发送 IM 回复。原始历史会保留。总结或压缩后的预算检查失败时，已有上下文和待处理消息仍然保留；处理报告的错误后再继续会话。

## 管理会话与聊天存储

开发版新增**设置 → 存储**，这些操作尚未随正式版发布。选择 Bot 后，可以看到它的聊天和其他未绑定会话，包括已归档、未归档对象；通过搜索或大小排序查找其他会话。进入聊天后，分别查看 IM 归档和当前 Astral 会话记录。

大小条是包含模型调用历史的逻辑内容估算。共享正文和数据库开销会使它与磁盘上的实际文件大小不同，不能直接相加，也不能用来预测删除后释放多少空间。可以按需刷新；统计不完整时会明确标记。

对于未绑定会话，**归档**会将它从普通最近会话中隐藏，**恢复**使它重新可用。**永久删除**只允许已归档且未绑定聊天的会话，并在删除前确认所选对象。它会移除该会话在 Astral 中的历史、模型调用记录、待处理输入、回忆索引和所属计划；独立分叉会话保留各自历史。电脑工作文件和外部平台消息保留。

对于绑定的聊天，按想移除的内容选择动作：

| 动作 | 影响 |
| --- | --- |
| **清理 IM 归档** | 移除所选日期之前、已可安全清理的 Astral 归档正文。当前会话历史和外部平台消息保留；尚待处理的消息暂不清理。 |
| **归档保留期限** | 默认**永久保留**。选择 **30、90、180 天**后，立即清理符合条件的过期归档，此后每天检查；改回永久保留会停止自动过期，但不会恢复已经删除的归档。 |
| **清理会话** | 停止当前工作，创建继承原私密设置的新会话，换绑聊天后永久删除旧会话及其计划。IM 归档、账号设置和外部平台消息保留。 |

归档清理保留轻量事件回执，避免平台重投后再次导入同一批旧消息。已经进入会话的内容继续保留，直到单独清理或删除该会话。普通的**更换会话**仍保留旧会话历史，只有明确的**清理会话**操作会删除它。

离开页面或连接中断后，清理任务仍使用原来的身份；结果不确定时先核对，再继续同一次任务，不重复创建删除。清理后后台数据库回收可能等待空闲，全量整理期间存储请求可能等待。逻辑删除完成与实际磁盘回收是两件事。文件清理、备份保护和回收状态见[存储维护](/zh-cn/docs/hosting/maintenance/#查看与清理存储)。

## 把不同工作分开

相关任务可以沿用一个会话，互不相关的工作可以新建会话。复制或分叉会话会产生独立会话，后续消息不会自动同步。

一个外部聊天与一个 Astral 会话绑定。更换绑定会保留原会话历史，具体行为见[接入聊天](/zh-cn/docs/chat/overview/)。
