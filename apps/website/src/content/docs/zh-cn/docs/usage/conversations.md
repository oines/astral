title: "使用会话"
description: "发起任务、补充要求、停止执行，并继续已有工作。"
---

一个会话属于一个 Bot，保存消息、执行记录和任务上下文。点击侧栏中的会话即可继续工作。窄屏上轻点一次进入会话，侧栏会收起；每行右侧的三个点用于打开会话菜单。

侧栏优先显示正在进行和已计划的会话，其次按 Telegram、QQ、微信、飞书组织绑定 IM 的会话，最后是普通会话的固定与最近分组。空组不显示，QQ 官方 Bot 与 NapCat 同属 QQ 分组；每个会话按此优先级只出现一次。

普通会话可以通过菜单重命名、归档或恢复；Bot 也可以通过 Gateway API 修改自己会话的标题和归档状态。绑定 IM 的会话使用聊天名称，不允许重命名或归档，菜单会隐藏这两个动作。要安排未来投递的 prompt，参阅[计划任务](/zh-cn/docs/usage/schedules/)。

## 发起任务

选择 Bot，新建会话，确认输入区域中的模型和电脑，然后发送任务。把希望得到的结果、需要使用的文件和重要限制说清楚。

电脑决定命令和文件操作在哪里执行。模型决定如何理解和推进任务。两者可以在会话中调整，无需为了换电脑另开一个会话。

## 私密会话

个人工作和群聊使用同一个 Bot 时，可以把个人会话设为私密，限制其他会话查询其中的记录。

在侧栏会话菜单中选择**设为私密**，会话旁会出现锁标记；选择**取消私密**可以恢复。你仍能通过 Desktop 和浏览器打开、管理它。

其他会话无法通过内置 API 发现、读取或修改私密会话，也无法访问它当前绑定的 IM 聊天和指向它的计划任务。私密会话可以访问自己的资源；分叉会话继承来源的私密设置。

私密会话仍会保存历史，并把执行所需的上下文发送给所选模型服务。共享电脑上的文件不会被隔离，此前已经复制到其他会话的信息也会保留。聊天解绑或换绑后，按新的会话关系应用权限。完整建议见[安全使用 Astral](/zh-cn/docs/start/safe-use/)。

## 任务运行时补充消息

所有会话的 Web 输入都支持两种方式，包括已绑定聊天平台的会话：

- **排队：** 当前一轮结束后再处理补充消息。适合下一步任务。
- **立即补充：** 尽快把新要求交给当前运行中的 Bot，在可处理输入的边界生效。适合纠正方向或新增限制。

尚未处理的排队消息可以编辑、删除或调整顺序。已经开始执行的操作不会因为补充一句话自动撤销。

接入聊天平台的会话中，Bot 工作时收到的聊天消息会进入后续模型步骤，无需另一次唤醒。空闲时，私聊、直接提及、回复 Bot 及平台支持的戳 Bot 会直接唤醒它；普通群消息遵循[主动参与设置](/zh-cn/docs/chat/groups/)。Web 输入遵循相同的模式偏好，默认排队。按 Command/Ctrl+Enter 可以直接立即补充。使用输入法确认候选词或英文时不会发送消息，确认后单独按 Enter 发送，Shift+Enter 换行。

## 停止与继续

点击停止后，等待状态确认。停止不会回滚已经修改的文件或已完成的外部操作；必要时检查执行记录和实际结果。

会话显示“继续”时，可以从已有上下文继续执行，也可以先发送新的说明。来源电脑离线或模型连接失效时，先恢复依赖再继续。

## 时区

在**设置 → 通用 → 时区**中选择时间显示与计划调度使用的时区。**跟随系统**采用 Astral 安装主机的时区。更改后，各客户端按新时区显示消息和计划时间；已有事件的发生时刻保持不变。

## 长会话

聊天先加载近期消息，向上接近顶部时继续加载较早历史；重连保留已加载的消息和阅读位置。本次打开期间切回仍在缓存中的会话，也会恢复已加载的历史和阅读位置，再同步新消息；刷新页面或缓存被淘汰后重新加载近期消息。

执行步骤的参数、文本输出和结果随消息页一起加载，点击展开即可查看。图片和附件仍按需读取；原始 Rollout 可通过**导出 Rollout**获取。Bot 输出时向上滚动会停止跟随，滚回底部或点击“回到最新”后恢复。

会话变长时，Astral 会调用模型总结较早的上下文，并保留近期消息。收到的聊天消息和图片都会占用上下文，包括 Bot 没有回复的消息。原始历史仍可查看。

总结失败时，已有上下文和待处理消息会保留。按错误提示处理后再继续会话。

## 管理会话与聊天存储

打开**设置 → 存储**，先查看磁盘用量，再选择 Bot，找到要清理的聊天或其他会话。进入页面和清理后会自动更新用量；也可以手动刷新。聊天按名称和平台辨认，同平台有多个账号时再补充账号信息。

列表中的“约”表示内容大小估算，用于比较哪些聊天或会话占用较多。实际磁盘用量显示在总览中；统计未完成或失败时会有提示。

未绑定聊天的会话可以**归档**或**恢复**。只有已归档且未绑定的会话可以**永久删除**。删除会移除其历史、模型调用记录、待处理消息、回忆索引和计划；独立分叉会话、电脑工作文件与外部平台消息保留。

对于绑定的聊天，按要清理的内容选择动作：

| 动作 | 影响 |
| --- | --- |
| **清理 IM 归档** | 删除所选日期之前的 Astral 聊天归档。尚待处理的消息暂时保留；会话记录和平台消息保留。 |
| **归档保留期限** | 默认**永久保留**。选择 **30、90、180 天**后，立即清理符合条件的过期归档，此后每天检查；改回永久保留会停止自动过期，已经删除的内容无法恢复。 |
| **清理会话** | 停止当前工作，永久删除旧会话及其计划，并为聊天创建一个继承原私密设置的新会话。IM 归档、账号设置和平台消息保留。 |

清理归档后，已经进入会话的内容继续保留，直到单独清理或删除该会话。**更换会话**会保留旧历史，适合希望另起话题、稍后仍能回看的情况。

清理后列表会更新，磁盘空间由 Astral 在后台回收，可能稍后释放。失败时按对应提示处理或重试。连接中断后先让页面恢复并检查结果，避免再次发起相同清理。备份和应用文件的处理见[存储维护](/zh-cn/docs/hosting/maintenance/#查看与清理存储)。

## 把不同工作分开

相关任务可以沿用一个会话，互不相关的工作可以新建会话。复制或分叉会话会产生独立会话，后续消息不会自动同步。

一个外部聊天与一个 Astral 会话绑定。更换绑定会保留原会话历史，具体行为见[接入聊天](/zh-cn/docs/chat/overview/)。
