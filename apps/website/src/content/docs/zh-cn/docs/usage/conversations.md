---
title: "使用会话"
description: "开始一项工作，途中补充要求，并找到之前的任务和结果。"
---

会话是你和 Bot 完成一项工作的地方。把任务发给它，可以接着提问、修改要求，之后再打开同一个会话继续。首次设置完成后，可以直接使用已有的 Astral Bot。

如果还没有可用的模型或电脑，先完成[模型配置](/zh-cn/docs/usage/models/)和[电脑连接与授权](/zh-cn/docs/computers/connect/)。模型负责理解任务；电脑负责保存文件和执行操作。

## 发起任务

在主界面新建会话，确认选中的电脑是你希望存放工作文件的那台。任务说明中最有用的是预期结果、要用的资料和重要限制。例如：

> 在当前工作目录创建“本周计划.md”，列出周一到周五的工作计划，每天留三个空白事项。完成后给我文件链接，并告诉我保存在哪台电脑、哪个目录。

完成后打开文件核对内容。如果需要上传资料或下载结果，接着看[文件与结果](/zh-cn/docs/usage/files/)。

## 任务运行时补充消息

补充要求时，按它应当何时处理选择发送方式：

- **排队**：等当前一轮结束后处理，适合“做完以后，再整理成表格”。尚未处理的排队消息可以编辑、删除或调整顺序。
- **立即补充**：尽快把要求交给正在工作的 Bot，适合“只处理今年的数据”或“先停下，保存位置改为另一个目录”。Bot 会在能够接收新输入时处理，已经开始的操作不会自动撤销。

Web 输入默认排队，可以在输入区选择方式；Command/Ctrl+Enter 直接立即补充。连接 Telegram、QQ 等聊天平台的会话也可以从 Astral 界面补充消息。平台里发来的消息如何唤醒 Bot，见[群聊与主动参与](/zh-cn/docs/chat/groups/)。

## 停止与继续

需要中断时点击停止，等会话退出运行状态。停止后，已经改过的文件和已经发出的外部消息仍然存在。如果正在做重要修改，先查看最后几条执行记录和实际文件，再决定下一步。

会话出现**继续**时，可以从已有内容接着执行，也可以先发送新的说明。例如：“先告诉我哪些文件已经修改，再继续剩余部分。”如果提示电脑离线或模型调用失败，先恢复相应连接。

会话空闲时，可以在输入区更换电脑；正在执行时，Bot 也可以按你的任务要求使用其他获准电脑。切换不会把文件带到另一台机器，具体见[跨电脑工作](/zh-cn/docs/computers/across-computers/)。

## 把不同工作分开

同一项工作的追问和修改留在原会话中，Bot 就能沿用前面的说明。不相关的工作可以新建会话，例如把“整理旅行照片”和“分析报表”分开。

归档适合暂时收起已经完成的普通会话，需要时可以恢复。绑定外部聊天的会话使用聊天名称，不能重命名或归档；要让聊天另起一段上下文，使用[更换会话](/zh-cn/docs/chat/overview/)，旧历史会保留。

复制或分叉会话适合从已有工作探索另一种做法。它会产生独立会话，之后两边的消息不会同步，也不会复制原会话的计划任务。

## 私密会话

如果个人工作和群聊使用同一个 Bot，可以把个人会话设为私密，防止其他会话查询这段记录。

在侧栏会话菜单中**设为私密**后，你仍能在 Desktop 和浏览器中打开、管理它。

私密会话及其当前绑定的聊天、指向它的计划任务，不会向其他会话的内置查询和修改功能开放。私密会话仍能访问自己的资源，分叉出的会话继承私密设置。聊天换绑后，权限跟随新的会话关系。

私密设置保护的是会话访问范围。历史仍会保存，执行任务所需的内容仍会发送给所选模型服务。同一台电脑上的共享文件，以及此前已复制到其他会话的信息，需要另行保护。涉及个人资料时，请阅读[安全使用 Astral](/zh-cn/docs/start/safe-use/)。

## 长会话

会话很长时，Astral 会让模型总结较早的内容，保留近期消息继续工作。原始历史仍可查看。聊天消息和图片即使没有得到 Bot 回复，也可能占用模型可处理的内容空间。若总结失败，已有内容和待处理消息会保留；处理页面显示的错误后再继续。

## 时区

在**设置 → 通用 → 时区**中选择消息时间和计划任务使用的时区。**跟随系统**采用安装 Astral 的那台主机的时区；如果你从异地浏览器访问，可能需要手动选择。

更改时区后，各客户端会按新时区显示时间，已有消息的实际发生时刻不变。设置未来执行的工作，请看[计划任务](/zh-cn/docs/usage/schedules/)。

## 管理会话与聊天存储

需要释放存储空间时，打开**设置 → 数据与存储**，先看总用量，再选择 Bot，找到要清理的聊天或会话。列表中的“约”是内容大小估算，适合比较谁占用较多；总览显示实际磁盘用量。

普通会话需要先归档，并且没有绑定聊天，才能**永久删除**。删除会移除其历史、模型调用记录、待处理消息、可供回忆查询的记录和计划任务。独立分叉会话、电脑工作文件和聊天平台上的消息保留。

对于绑定的聊天，先区分两种记录：**IM 归档**是 Astral 留存的平台聊天内容；**会话**是 Bot 围绕这些内容形成的任务和执行记录。按需要选择：

| 你想清理什么 | 使用哪个动作 | 会发生什么 |
| --- | --- | --- |
| 较早的平台聊天归档 | **清理 IM 归档** | 删除所选日期之前的归档，尚待处理的消息暂时保留。会话记录和平台消息保留。 |
| 以后定期清理旧归档 | **归档保留期限** | 默认永久保留。选择 30、90 或 180 天后立即清理符合条件的旧归档，之后每天检查。改回永久保留会停止自动清理，已删除内容无法恢复。 |
| 当前聊天的整段任务历史 | **清理会话** | 停止工作，永久删除旧会话及其计划，并创建一个继承原私密设置的新会话。IM 归档、账号设置和平台消息保留。 |

已经进入会话的内容，不会因清理 IM 归档而消失；需要单独清理会话。如果只是想开始新话题并保留旧历史，使用**更换会话**。

清理后列表会更新，实际磁盘空间可能稍后才释放。失败时按对应提示重试；如果中途断线，先恢复页面并查看结果，避免重复发起。备份和应用文件清理见[存储维护](/zh-cn/docs/hosting/maintenance/#查看与清理存储)。
