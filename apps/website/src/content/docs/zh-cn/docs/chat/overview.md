---
title: "接入聊天"
description: "在 Telegram、QQ、微信或飞书里直接交代任务，让 Astral 用你的电脑做完再把结果发回来。"
---

接入聊天平台后，你可以随时在手机或桌面聊天软件里给 Astral 派活，它会在你授权的电脑上完成任务，再把结论或文件发回原聊天。**每个接入的聊天对应一个独立的 Astral 会话**，在聊天里和网页里看到的是同一段工作记录。

:::tip[先跑通本地任务]
建议先在 Astral 界面内[完成第一个任务](/zh-cn/docs/start/first-steps/)，再接入聊天平台。收发消息期间 Astral 必须保持运行；想合上电脑也全天在线，请看[选桌面版还是 Server](/zh-cn/docs/hosting/architecture/)。
:::

## 1. 选择平台并连接账号

打开 **设置 → Bot → 目标 Bot → 连接平台**，按账号类型对照下面指南配置：

| 平台 | 接入方式 | 支持范围 |
| --- | --- | --- |
| **[Telegram](/zh-cn/docs/chat/telegram/)** | 通过 BotFather 获取 Token | 私聊、群聊 |
| **[QQ](/zh-cn/docs/chat/qq/)** | 普通 QQ 号（NapCat）或 QQ 开放平台官方 Bot | 私聊、群聊 |
| **[微信](/zh-cn/docs/chat/weixin/)** | 微信扫码授权 Bot | 目前仅私聊 |
| **[飞书](/zh-cn/docs/chat/feishu/)** | 企业自建应用机器人（权限、发布与事件） | 私聊、群聊 |

一个 Bot 可以挂载多个平台账号，每个账号各自管理凭据和聊天列表。

:::caution[公开群务必隔离]
群内成员都能指挥 Bot 使用它已获准的电脑和聊天账号权限。接入公开群前，请先准备专用 Bot 和[独立执行环境](/zh-cn/docs/start/safe-use/#公开群聊使用独立环境)。
:::

## 2. 选择允许接入的聊天

新账号默认处于**仅指定的聊天**模式（列表为空），最安全：

1. 按对应平台指南发现目标聊天或取得 Chat ID，在账号的**已接入聊天**中添加。
2. 决定上下文起点：选**新会话**从空白开始，或绑定同一 Bot 下尚未绑定其他聊天的**已有会话**（接入群聊前确认旧内容适合群成员看）。
3. 如果希望机器人自动响应所有新私聊或群内首次 `@`/回复，可切换为**机器人能访问的全部聊天**——范围会明显扩大，只服务少数聊天时保持指定模式即可。

## 3. 发一条新消息验证接通

添加完聊天后，回到原聊天软件，**发送一条新消息**（群里请 `@` Bot 或回复它；之前用于发现聊天的旧消息不会自动触发任务）：

> 请在这个聊天里回复“连接成功”，并告诉我你当前使用哪台电脑。

在 Astral 对应会话看到处理过程，同时在聊天软件里收到回复，就说明完全接通了。接下来可以发张图片或小文件，让它读取并把结果发回来。

:::note[让 Bot 明确把结果发回聊天]
Bot 在 Astral 里输出的工作过程只在网页可见，聊天软件里的成员看不到；只有调用发送工具（`send_message`）才会发到原聊天。需要拿到文件或结论时，顺手说一句“发回这个聊天”。
:::

## 日常管理速查

| 你想做什么 | 怎么操作 |
| --- | --- |
| 调整群里何时回应 | 默认仅被 `@` 或回复时处理；普通讨论如何参与见[群聊协作](/zh-cn/docs/chat/groups/)。 |
| 单独移除某个聊天 | 先切回**仅指定的聊天**（已有聊天列表和设置会保留），再移除目标项。 |
| 暂时停用账号 | 关闭**启用账号**停止接收新消息，历史保留（已在跑的电脑任务需到会话里手动停）。 |
| 给聊天另起一段上下文 | 使用**更换会话**，原会话和目标会话都会先停止运行并保留各自历史（若选归档会话，需先恢复）。 |
| 查群成员、管群文件 | 直接用自然语言交给 Bot 即可；仅需自定义脚本调用时才看[平台 API](/zh-cn/docs/chat/platform-api/)。 |

<summary>查看遗漏回复补提醒与模型异常恢复细则</summary>

- **直接触发未发消息时的补提醒**：处理私聊、`@` 或回复等直接触发消息时，如果 Bot 正常结束却没有调用发送工具，Astral 会再提醒它一次。提醒后它仍可选择不回复，不会把工作过程自动发到聊天。这项机制不适用于群聊主动参与，也不会重发已经失败或结果未确认的发送。
- **模型额度/凭据异常**：遇到额度不足、凭据失效或无权限时，会话会保留错误并暂停处理，但仍继续接收与归档聊天消息。修复后到对应会话发新输入，或切换为可用模型，即可自动继续处理等待中的消息。限流与临时网络故障会按间隔重试，连发消息不会加速。
- **摘要超出上下文窗口**：若长会话摘要超出所选模型窗口，处理会暂停并保留待处理消息。更换更大窗口的模型或修正模型窗口配置后，系统会重新尝试压缩并继续运行。

</details>
