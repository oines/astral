---
title: "连接飞书"
description: "创建飞书应用、开通消息权限，并把一个私聊或群聊接到 Astral。"
---

你需要在飞书里创建一个**企业自建应用**，给它开启机器人能力，再让 Astral 使用这个机器人收发消息。群设置里的自定义 webhook 机器人只能推送通知，不能用于这里的双向聊天。

开始前，准备能管理自建应用的飞书账号，并确认 Astral 已完成[模型和电脑配置](/zh-cn/docs/start/first-steps/)。应用权限和发布可能需要企业管理员审核，先把自己和测试成员加入可用范围即可。

整个顺序是：**创建应用 → 开通权限并首次发布 → 连接 Astral → 设置事件并再次发布 → 添加聊天并验证**。首次发布让机器人可用；连接 Astral 后，飞书才允许保存长连接事件配置。

## 1. 创建应用，取得 App ID 和 App Secret

1. 打开[飞书开发者后台](https://open.feishu.cn/app)，创建企业自建应用，填写你希望在飞书中显示的名称等信息。
2. 进入该应用，在 **添加应用能力** 中添加 **机器人**。
3. 打开 **凭证与基础信息**，找到 **App ID** 和 **App Secret**。保留这个页面，稍后要将这两个值复制到 Astral。

App Secret 是连接凭据，不要发到群聊里。Astral 连接表单中的 **配置飞书应用** 也可以打开开发者后台；填入 App ID 后，会直接打开该应用的权限管理页。

## 2. 开通权限并首次发布

在应用的 **开发配置 → 权限管理 → 批量导入/导出权限** 中选择导入，粘贴下面的完整 JSON。点击 **下一步，确认新增权限**，再 **申请开通**。这些是应用身份权限，`user` 保持为空。

```json
{
  "scopes": {
    "tenant": [
      "im:chat:readonly",
      "im:message:readonly",
      "im:message.p2p_msg:readonly",
      "im:message.group_msg",
      "im:message:send_as_bot",
      "im:resource",
      "im:message.reactions:write_only"
    ],
    "user": []
  }
}
```

这些权限分别负责：

| 你需要的功能 | 权限 |
| --- | --- |
| 接收用户给机器人的私聊 | `im:message.p2p_msg:readonly` |
| 接收群消息，包括提及；读取群消息和群内引用 | `im:message.group_msg` |
| 读取消息、下载收到的附件、读取表情回应 | `im:message:readonly` |
| 发送消息、撤回 Bot 自己的消息 | `im:message:send_as_bot` |
| 上传图片和文件 | `im:resource` |
| 读取聊天资料，例如群名 | `im:chat:readonly` |
| 添加和移除 Bot 自己的表情回应 | `im:message.reactions:write_only` |

`im:message.group_msg` 属于敏感权限，需要按企业要求申请。它也用于读取群消息和引用，不只是“主动参与讨论”的开关。仅开通上传权限 `im:resource` 不能满足读取收到的附件所需的权限。

然后打开 **版本管理与发布**，创建版本，将自己和测试成员加入应用的 **可用范围**，提交发布并完成所需审核，确认应用已启用。权限显示“待发布”时，还没有随线上版本生效。已有权限可保留，批量导入会跳过重复项。

## 3. 在 Astral 连接应用

在 **设置 → Bot → 目标 Bot → 连接平台 → 飞书** 中，把飞书 **凭证与基础信息** 页的 App ID、App Secret 复制到连接表单，通常保留默认服务器地址。连接后保持 Astral 运行，继续配置飞书事件。

如果提示机器人尚未激活，先完成上一步的发布、启用和审批，再重新连接。

## 4. 配置消息事件，再发布一次

在飞书后台打开这个应用的 **事件与回调 → 事件配置**：

1. 将订阅方式改为 **使用长连接接收事件**，保存。此时 Astral 必须已经连接并保持运行。Astral 主动连接飞书，无需填写公开 webhook 地址。
2. 点击添加事件，加入以下三项：

   | 事件标识 | 用途 |
   | --- | --- |
   | `im.message.receive_v1` | 接收聊天消息 |
   | `im.message.reaction.created_v1` | 接收新增表情回应 |
   | `im.message.reaction.deleted_v1` | 接收移除表情回应 |

3. 返回 **版本管理与发布**，创建并发布新版本，使事件配置和仍待发布的权限生效。

保存长连接失败时，先检查 Astral 中的账号是否已连接，以及运行 Astral 的机器能否访问飞书。飞书要求客户端在线后保存订阅方式，详见[长连接配置说明](https://open.feishu.cn/document/ukTMukTMukTM/uYDNxYjL2QTM24iN0EjN/event-subscription-configure-/request-url-configuration-case)。

## 5. 添加聊天，验证真实回复

用应用可用范围内的用户在飞书发起私聊，或把机器人加入目标群，再发送一条“你好”；群里真正 **@ Bot**。这会让 Astral 发现聊天，随后在该账号的 **已接入聊天** 中添加它并选择会话。

添加后回到飞书，**重新发送**“请在这个飞书聊天中回复：连接成功”。群里同样要提及 Bot，或回复它发过的消息。在 Astral 检查处理过程，再到原飞书聊天确认实际回复。发现聊天用的旧消息不会在添加后自动执行。

需要手工查找时，用 Astral 实际收到的 `oc_…` 形式 Chat ID。飞书线程当前和父聊天共用授权及 Astral 会话。

## 图片、文件和群讨论

接通后，用一张图片或一个小文件测试读取和发送。图片可与文字、原生提及组合发送；普通文件与说明文字分开发送，请确认附件也已到达。

上面的权限包含普通群消息。Astral 默认被提及或被回复时处理任务，主动参与需按群开启，见[群聊协作](/zh-cn/docs/chat/groups/)。查询消息和表情回应等自定义调用见[平台 API](/zh-cn/docs/chat/platform-api/)。

## 卡在哪一步，就检查哪里

| 现象 | 检查方法 |
| --- | --- |
| Astral 提示机器人未激活 | 在飞书完成首次发布、启用和管理员审批 |
| 无法保存长连接订阅方式 | 先连接 Astral 账号并保持运行，再保存事件配置 |
| 飞书找不到应用或用户无法私聊 | 把用户加入应用可用范围，发布配置；检查是否被企业管理员禁用 |
| 账号已连接，却发现不了聊天 | 检查 `im.message.receive_v1`、消息权限和新版本是否生效；群聊还需机器人已入群 |
| 只能显示 Chat ID，没有群名 | 检查 `im:chat:readonly` 是否生效 |
| 文字能收到，附件或引用读取失败 | 检查 `im:message:readonly`；群消息还需要 `im:message.group_msg`，并发布权限变更 |
| 聊天已添加，仍没有回复 | 在飞书重新发任务，群里真正 @ Bot；到 Astral 检查模型、电脑和平台发送错误 |

发送超时或结果不确定时，先检查飞书中的实际消息，再决定是否重发。
