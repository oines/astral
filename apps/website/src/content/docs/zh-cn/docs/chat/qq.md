---
title: "连接 QQ"
description: "选择官方 Bot 或 NapCat，配置账号并接入私聊或群聊。"
---

Astral 提供两种 QQ 接入方式。创建账号时先选对方式；它们使用不同凭据和聊天标识，不能混用。

| 方式 | 凭据 | 聊天标识 |
| --- | --- | --- |
| 官方 Bot | App ID、App Secret | `private:<user_openid>`、`group:<group_openid>` |
| NapCat | HTTP 地址、正向 WebSocket 地址、Access Token | `private:<QQ号>`、`group:<群号>` |

## QQ 官方 Bot

1. 在 [QQ 开放平台](https://q.qq.com/)创建 Bot，取得 App ID 和 App Secret。
2. 在平台配置可用的测试用户、测试群或发布范围，并授予需要的私聊、群消息和发送权限。
3. 在 Astral 选择 **连接平台 → QQ → QQ 官方 Bot**，填写凭据并连接。
4. 从获准用户或群给 Bot 发消息，让 Astral 发现聊天，再完成聊天授权与会话绑定。

默认 API 地址和 Token 地址通常不需更改。Astral 主动连接平台网关，不要求你提供公开 webhook。

官方 Bot 的 openid **不是 QQ 号或群号**，不能跨应用复用。当前支持私聊和获准的群，不接入 QQ 频道。普通群消息能否收到、何时可以回复、能发送哪些文件，都受账号实际权限和平台规则限制。当前群聊/C2C 接入不支持消息表情回应，不能沿用 QQ 频道的能力。

## QQ NapCat

先按 [NapCat 指南](https://napneko.github.io/)安装服务并登录目标 QQ 账号，然后配置：

1. 启用 HTTP 服务端。
2. 启用能够接收事件的**正向 WebSocket**服务端，不使用只处理 API 的 `/api` 端点。
3. 两端使用相同 Access Token，消息上报格式设为 `array`。
4. 如果需要读取远程 NapCat 主机上的附件，启用 `enableLocalFile2Url`，使文件接口能返回内容，而不只是本地路径。

在 Astral 选择 QQ NapCat，填写 Server 实际可达的两个地址与 Token。HTTP 和 WebSocket 必须对应同一个 QQ 账号。`127.0.0.1` 只有在 NapCat 与 Server 位于同一机器或适当网络环境时才适用。

## 完成接入并验证

在账号的聊天接入区域添加目标私聊或群，选择会话。群里明确提及 Bot，先验证文本回复，再测试文件发送。

NapCat 发送普通文本，Markdown 标记不会自动渲染。断线期间的消息没有自动历史重放；恢复连接不意味着已经补齐漏掉的消息。若发送结果不确定，先检查聊天实际状态，避免重复发送。

## NapCat 引用、戳一戳与撤回

回复的原消息已在同一聊天的 Astral 归档中时，上下文会带上原文、卡片、合并转发树与媒体引用，不会自动将原件另存为文件。找不到原记录时会明确说明，不会跨聊天查找或自动拉取这条缺失的原消息。

戳一戳以独立事件呈现操作者、被戳的人，以及 NapCat 提供的动作文字和自定义后缀。别人戳当前 Bot，可以在已经授权、绑定会话的聊天中唤醒它；其他人互戳、Bot 自己发起的动作仍是被动上下文。

撤回会追加一条说明操作者和原消息的事件，不删除或改写 Agent 已经收到的上下文。这些事件沿用消息的聊天权限，不会自动授权新聊天。NapCat 不补放断线期间的消息；分别收到的通知即使可见内容相同，也会分别记录。

## 卡片与合并转发

Bot 可以读到 QQ 卡片的来源、标题、描述和链接，平台名与视频的实际标题会分别保留。合并转发保留原消息顺序、发送者和已有时间，也支持其中继续包含转发、卡片及媒体。卡片上显示的摘要不会冒充完整转发记录，也不会当作链接网页的正文。

Astral 先展示小范围预览。NapCat 已提供的内容在本地解析；只提供转发引用时，自动解析共用总计 6 秒、2 层与 12 条子消息的预算。较长、较深或暂时不可用的内容保留明确状态和读取链接，Bot 需要时再跟随链接分页展开，不会为了无限展开而堵住后续收信。

转发中选中展示的图片沿用现有内存预览，最多 75,000 总像素，作为图片输入交给模型；该预览随会话历史保存，原图下载地址仍然保留。接收时不另存原图、文件或创建 FileRef。视频和普通文件只提供元信息与原件下载地址，Bot 需要实际文件时再主动下载。可选图片预览失败会保留原件引用，不阻塞后续消息。

所有读取和下载都沿用最外层 QQ 账号、聊天和原消息的权限。转发里引用的人、@ 和聊天标识不会唤醒 Bot，也不会授予另一个聊天的访问权限。新行为只影响新构造的上下文，不重写既有会话上下文或摘要。

Bot 可以通过认证 Gateway 发现消息的 `/parts` 索引，再跟随读取链接展开内容。读取原始卡片 JSON、将原件下载到指定电脑路径都是显式操作；这些读取不会新建会话或修改消息归档。

## NapCat 表情回应与主动戳一戳

NapCat 可以提供部分群消息表情回应通知，主要针对登录账号自己发出的消息。Astral 追加回应事件，保留 QQ 表情 ID 和实际收到的操作者；缺失身份会明确为未知。NapCat 提供的数量保留为原始报告值，不当成可靠的总数，也不补造未收到的通知。已知自身动作不唤醒 Bot；操作者未知的回应只作为旁观上下文，不单独启动参与判断，工作中的 Bot 仍能读到。已知其他人的群回应沿用可选主动参与规则。

Agent 可以通过现有 Computer API 的 `set_reaction` 为已归档且归属已核实的消息添加或取消回应，通过 `poke` 主动戳人。群聊必须指定并核实目标群成员；私聊只能戳当前对方。它们沿用当前账号和聊天权限，不改变 `send_message`。

私聊窗口抖动与戳一戳是两个功能。收到窗口抖动时，上下文会显示 `[QQ private window shake]`；当前 NapCat 没有可用的窗口抖动发送接口，因此 Astral 暂不支持主动发送抖动，不会用戳一戳冒充。
